# v1.0 核心范围与预测验收

2026-10-09候选rc60新增浏览器内已有号码参考实验：同源连续曲线、快慢情景与失效暂停已实现，时间顺序回放发现远期偏差；实际叫号误差、历史冷启动、AI收益与两种预测验收仍未完成。云端原页面未部署此实验，见[研究与限制](REFERENCE_POSITION_RESEARCH.md)。

2026-10-08 用户允许先不做个人前方桌数、自动取号、取消和重排，改为输入自己已有的号码，实时预测等待时间。当前这些业务环节的提交参数、长期个人授权更新及失败对账尚未完成，因此采用这一分期方案。原自动操作需求与本人授权保留，后置到核心版之后；不是已实现，也不是永久删除。完整变更见[交接记录](PROJECT_HANDOVER.md)的 R30–R35 和 E0288–E0290。

## 首先交付的体验

用户在官方客户端正常取号，再在本项目选择门店、堂食或预约队列、输入号码，补充已知的取号时间、人数／桌型和签到状态。未知信息可以保持未知，不能补造时间。号码和私人用餐计划按私有资料处理，不送给 DeepSeek 或公开日志。

系统共享采集门店观测，在有可验证模型时更新剩余等待和叫号时间区间。临近到店按前 30 分钟 60 秒、前 15 分钟 30 秒的目标频率采集；提醒源数据陈旧、异常加速和提前到场风险。刷新频率不是防过号保证，提醒送达需要单独实测。

保留原两种预测及理想时间的 `+10`／`-10` 语义：已有号追踪是第一优先入口；未取号的假设等待和反向建议取号时机仍需相应真实资料及误差校准。用户自行执行建议的取号动作，不自动取、取消、签到或重排。不能以“手动号码版”为由静默删掉日期趋势、误差、防过号或理想时间要求。

门店按实际能力分级：已验证实时展示、可研究但预测未校准、预测已验收、数据不足。目录覆盖与预测覆盖分别说明。先验收三试点，再分批扩展；当前不是全国预测服务。

## 号码差怎样使用

用户补充：门店顺序发号，前方号码包含已签到和未签到桌。这是重要的待核实业务假设。如果同店、同队列、同发号周期内号码连续且每号对应一桌，自己的号码与有效推进位置的差值可作为前方已发号位置的近似特征。边界是否包含自己与正在叫的号要固定定义；不能直接给它换成现场已签到等待桌数。

当前拿到的前三位是有限展示集合，不自动等于完整队列或最后实际叫号游标。不能随意取数组最小／最大值当游标。需验证队列归属、展示排序、签到插回、重置及号码前后缀；预约和堂食不相减。缺乏可靠推进位置时保留候选距离／范围和未知标记。

时间估计需要同时学习号码位置、已签到信息和实际推进速度。未签到或弃号可快速跳过，使号码推进和餐桌周转分离。候选特征包括短期推进／展示变化、速度异常、签到聚合、星期／日型／时段、月份与季节。取号人数和桌型在资料可得时另行考虑。差值值得使用，具体转换与权重由真实叫号结果检验，不能固定成“一号等几分钟”。

## 开发顺序

1. 验证并交付采集统计页，保持原三日任务、期限和预算；指定服务器上先少店验证，再累积长期资料。
2. 核实号码差的业务条件与推进位置，采集正常用餐结果，组合已接收的实时／日期特征；不靠反复取号制造标签。
3. 接入手动号码追踪的实时模型，进行时间顺序回测与真实试点，校准区间和两种预测。
4. 完成共享更新、实际提醒及用户界面；产品前端仍遵守先真实数据验证的 R18。用户明确新增的运行统计页只展示已保存资料。
5. 大模型按公共实时趋势与事件契约参与状态判断和受限数值融合，供应商可替换，密钥单独私有提供；不借个人号单或模型文本自动操作业务。

大模型格式依据：[DeepSeek 官方接口入口](https://api-docs.deepseek.com/)、[JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)。官方 JSON 模式仍可能空输出，应用必须验证并处理失败；本轮只是核对文档，不代表付费调用或预测收益已经验证。

最新四层实时数值方案与论文依据见[REALTIME_PREDICTION_MODEL](REALTIME_PREDICTION_MODEL.md)，供应商与官方价格/许可见[LLM_MODEL_CHOICES](LLM_MODEL_CHOICES.md)，扩店实际范围见[STORE_EXPANSION](STORE_EXPANSION.md)；当前仍未训练、调用或校准。
