# 本机短窗关闭保护

rc8新增、rc72修正 `surge-guard`：单独运行的本机进程，准备后在1–45秒截止时依次关闭解密及原始捕获，再检查解密、原始捕获及autoMitM均OFF。默认40秒。它不启用调试、不打开微信、不读取请求或凭证，不恢复域名名单，也不提供自动登录或续期。

## 使用顺序

仅用于本人已授权的本机正常查询短窗，当前授权域名是 `sapi.sushiro.com.cn`。先核对解密、原始捕获和autoMitM全部关闭，在界面准备唯一域名；接收器与保护进程分别运行。不要在采集仍发请求时开启解密：采集保持完整TLS验证，临时代理证书可能使查询失败。应等待实际保护暂停，或使用已验证的互斥协调器。

```sh
sushiwait surge-guard --seconds 40
```

看到 `surge_guard_ready` 后，必须核对进程仍运行、截止尚未到达以及单域名名单，再执行已授权的正常客户端操作。看到ready不是永远可以开启的许可；超过截止或保护进程退出，不得再开启。独立运行的 `context-surge` 只接收摘要，不替代此保护，也不会关闭开关。

等待 `surge_guard_finished` 和 `verified_off=true`，再在界面复核三个开关关闭、恢复原域名名单。按本人最新要求，保留官方小程序和Surge打开。正常上下文可以先接到独立私有暂存文件，调试已关闭后再用已有完整校验及原子写入机制提交给暂停的采集任务；不能提前把暂存上下文送给正在查询的任务。

## 已实现的防护

- 固定已安装macOS CLI路径，仅允许 `environment --raw`、`set MitMEnabled=0` 和 `set Replica=0` 三个命令。截止时两个OFF均尝试，即使第一个失败；随后回读三开关，命令或回读任一失败仍报告清理未确认。其他平台、路径缺失或命令不符拒绝执行。
- 初始三个开关任一ON、结构缺失、未知类型或重复JSON键均拒绝准备；不会接管原有调试。严格接受布尔、整数0/1及实际观察到的字符串0/1。
- CLI结果仅在内存处理，单次上限64KiB/3秒；超时或超限回收子进程，不输出原始环境或stderr，只输出三个白名单开关和固定错误码。
- 单调与墙上时钟双重截止；时间倒退走异常清理。SIGINT/SIGTERM请求提前关闭；ready输出异常也执行清理。失败不输出未经确认的关闭成功。
- 不发门店查询，不读取凭证，不修改代理路线、CA或服务端证书验证，不启用原始磁盘捕获或控制接口。

## 实际验证与限制

2026-10-10晚间新源码两轮实测：40.077秒与45.087秒截止后解密／捕获／autoMitM均OFF、exit0，Surge继续运行。命令set Replica=0曾被自动审批以状态变更为由拒绝；本人明确批准“允许，仅关闭捕获”后执行成功，未绕过审批。另一次35秒私有观察包装结果单独记交接，不当公开命令实测。87项接入／守护／窗口专项0.486秒通过，包括首个OFF失败仍尝试第二个、末次回读失败、真实子进程信号及首页来源隔离；不重复旧全套或把合成场景当真实续期。以下rc8实测保留原日期。

23项专项0.212秒、完整395项4.672秒通过，无跳过，既有26个JS场景已包含。专项包含真实本机子进程超时/超限回收及实际SIGTERM交付；模拟开关状态只验证控制逻辑，不冒充Surge真实开启证据。

项目新命令03:54:58.646–03:55:00.681实际保持全部OFF，2.035秒后关闭并回读成功、exit0。先前本机私有研究程序曾在真实正常查询窗口实测40.122秒自动关闭，见交接E0101；这两个程序及两类实测分别记录，不把私有程序成绩借作新命令的ON→OFF验证。新命令随后在正常8目录更新实测：04:13:16.195准备，单域名开启后04:13:56.230自行关闭，40.035秒/exit0且三个OFF，界面核对关闭、随后恢复原名单；接入写暂存，关调试后才原子提交，原三店任务独立恢复成功。完整更新协调/各故障仍待另验，见E0106。

这是发出OFF并回读的有界工具。SIGKILL、系统睡眠、Surge不可用、输出阻塞或操作者在退出后再次开启，可能使调试时长超过预期；没有宣称所有故障下60秒保证。rc72已修复只关闭解密而遗留捕获的问题，同时发出捕获OFF；仍不修改autoMitM。初始开关任一ON时仍拒绝接管，autoMitM后来被他人开启时报告未确认清理。域名恢复、客户端导航、任务暂停协调及常驻守护仍需完整控制器。
