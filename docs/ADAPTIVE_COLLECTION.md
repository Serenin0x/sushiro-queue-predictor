# 有界自适应采集

`monitor-collect` 把已经实现的单人时间策略、同店需求合并接入正常只读查询。它在一个进程内按当前最紧迫计划调整节奏：用餐前30分钟目标60秒，前15分钟及已到目标时刻仍在等待时目标30秒，窗口外使用明确的60–3600秒基础周期。提前叫号估计或展示集合加速输入只能提前加密刷新，不认证预测或真实过号率。

这是有界验证入口，当前没有长期后台服务、跨进程共享调度、计划动态重载、自动更新客户端、提醒或取号操作。安装模拟和真实短时试验分别记录在[交接文档](PROJECT_HANDOVER.md)；不能以合成时钟成绩代替真实频率或源刷新验收。

## 输入与运行

只读取本人明确指定的16KiB以内JSON，父目录0700、文件0600、本人所有、单链接、没有符号链接。使用[同店共享策略](SHARED_MONITORING.md)的schema1，最多128份计划/3店；新入口不接受外部`last_poll_started_at`，实际请求开始时间由本进程记录。启动时复制计划，后续文件修改不改变这次任务。

以下是合成计划格式，900001不能用于真实门店查询；时间仅展示字段形状，不代表预测或真实行程：

```json
{
  "schema_version": 1,
  "plans": [
    {
      "store_id": "900001",
      "desired_arrival_at": "2020-01-01T00:10:00Z",
      "call_offset_minutes": 0,
      "plan_status": "waiting"
    }
  ]
}
```

需使用已验证门店与本人授权的私有查询上下文。一次任务显式列出1–3个允许门店；计划中的每家店，包括已经结束的计划，必须在名单内。计划、凭证、数据库路径不能相同，也不能是同一个现有文件的硬链接。数据库推荐放在既有私有运行目录，命令不输出计划正文或个人理想到店时间；查询快照和运行输出仍需私有处理。

```sh
sushiwait monitor-collect \
  --api-profile miniapp_gateway \
  --plans-file /private/runtime/plans.json \
  --credentials-file /private/runtime/gateway.json \
  --store-id 3004 \
  --db /private/runtime/adaptive.sqlite3 \
  --base-interval 300 \
  --duration-seconds 300 \
  --max-queries 10
```

路径是占位示例，工具不会发现或创建凭证。时长限30–3600秒，查询预算全店合计1–360次；默认300秒/120次。已有`collect`的有界任务、显式恢复和可选凭证等待保持原样；新命令尚不支持这些选项，也不会启动认证或接收窗口。

## 实际调度语义

- 同店多个等待计划取最短周期，每个到期只做一次查询；不同门店分别计时，使用顺序GET。
- 周期锚定本进程紧邻查询调用前记录的实际开始；单调时钟决定等待和总截止，带时区时钟用于时间窗口。30/15分钟边界会提前唤醒重算。时间倒退、非法时间和非法计划有序拒绝。
- 慢查询或长暂停后只执行当前应到的一次；不补发漏掉的周期。每家店完成后重新核对总预算和截止。截止只禁止新的开始，不强行截断已经发出的HTTP请求；实际HTTP开始仍以快照中的传输计时为证。
- 每次GET前及等待期间沿用现有私有凭证重读/版本检查/声明到期前30秒保护。保护停止是preflight记录，HTTP失败是request记录，两者分开；首错停止、没有自动重试。
- 全部计划结束或空计划时退出，不读取凭证、不创建快照库。完成输出是实际启动/成功数及边界标志，不是所有用餐计划已完成的证据。

关闭或过期凭证需由独立的正常客户端更新流程处理。纯调度库提供恢复后延迟计算，当前命令遇到保护立即返回，不调用该恢复接口；不能称已交付无感续期。保持一个协调采集进程，其他进程没有共享去重或全局配额保证。

## 验收范围

源码专项覆盖60/30窗口、边界唤醒、同店合并、异店周期、偏移、截止/预算、慢预检、首错停止、等待中到期、终态零查询、私有输入和文件冲突。安装检查用明确的合成时钟和注入查询，900001在0/30/60秒得到三次回调，socket/native/子进程/真实凭证调用为0；它不会访问寿司郎。

真实查询是否达到目标周期、源是否变化、门店是否营业及字段含义需要独立实测。当前`eta_available=false`、`source_freshness=unknown`、`true_no_show_rate=null`、`notification_sent=false`、`business_operation_performed=false`，不保证防过号。后续接入真实预测、计划状态更新、提醒与长期凭证协调时，分别补充验收。
