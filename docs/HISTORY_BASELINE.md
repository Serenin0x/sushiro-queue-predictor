# 历史区间预测基线：研究入口与实际边界

候选 rc38 提供 `baseline-research`：从已接收并有当前确认声明的经历中，计算新加入等待、已等待但未叫号的剩余等待，以及理想到店时间的候选取号时刻。它是可解释的历史研究基线，尚未经过真实结果回测或区间校准；`eta_available=false`，当前真实训练标签为零。实时号码、异常加速、外部事件与 LLM 尚未成为本入口的输入，不能用于自动取号、取消或提醒。

来源是独立[结果接收库](OUTCOME_INTAKE.md)和[审核声明库](OUTCOME_REVIEWS.md)，只读核对两份完整有界修订历史。只有本机实际接收时刻不晚于 `as_of` 的结果和审核能进入候选；结果纠错会使旧审核过时，多个结论有冲突或证据不足时不使用该经历。审核是人工声明，仍不认证身份、事件真实性或训练资格。合成与人工资料、接口 profile 分开，不把公共展示号出现或消失变成叫号标签。

## 私有输入和输出

在三个已存在的私有目录中分别保存源库、审核库和输入/输出。POSIX 目录要求 0700、输入与输出文件 0600；不要放入仓库、公共日志或 LLM。输入最多 16 KiB，必须符合精确字段集合，不接受凭证、票号、自由文本或额外字段。

公共字段如下；示例 ID `900001` 是合成门店，不能拿来访问真实服务：

```json
{
  "schema_version": 1,
  "as_of": "2026-10-06T12:30:00+08:00",
  "data_origin": "synthetic",
  "api_profile": "miniapp_gateway",
  "store_id": "900001",
  "queue_type": "ordinary",
  "party_size": 2,
  "table_type": "unknown",
  "mode": "new_join",
  "minimum_samples": 1,
  "target_episode_id": null
}
```

所有时刻带时区和秒，输出规范化为 UTC。`as_of` 不得晚于调用时刻。`minimum_samples` 是调用者明确指定的 1–1000 个可计算样本门槛，不能作为稳定性、代表性或准确率保证。`party_size` 可为未知 null；队列只支持明确 ordinary/reservation，桌型 booth/counter/either/unknown 按原值精确匹配。

```bash
sushiwait baseline-research --source-db /private/source/source.sqlite3 \
  --reviews-db /private/reviews/reviews.sqlite3 \
  --input /private/output/plan.json --output /private/output/research.json
```

`--max-revisions` 默认及上限 10000，分别限制两库完整历史，不静默截断。输出最多 2 MiB，原子发布且不覆盖已存在路径。终端只输出模式、样本数量、研究候选可用状态和固定错误码；具体门店、计划时刻、候选叫号时间及历史指纹只在私有文件。发布后持久化确认失败显式返回 `committed=true/durability_confirmed=false` 和非零退出码，不把已发布文件说成未写入。

## 匹配历史与区间分位数

先精确匹配店、profile、资料来源、队列、人数和桌型；如果指定 `target_episode_id`，整个目标经历排除。不会退到其他门店或虚构全国平均值。取号至叫号等待保留区间：下界为 `max(0,叫号下界−取号上界)`，上界为 `叫号上界−取号下界`。本研究入口只处理不超过 48 小时的区间，超范围计数排除；这个上限不是门店业务规则。

从细到粗尝试四层：

1. 日型、节假日名称及假期序号、调休归属、星期、月份、日历季节与小时。
2. 日型、节假日名称、调休归属与小时。
3. 日型、节假日名称与调休归属。
4. 同店同队列同人数桌型的全部可用历史。

每次尝试记录匹配数量，实际退层明确标记。细层要求日历可用，且取号区间两端均匹配；跨小时区间不会被武断分到某一小时。不覆盖年份或未发布日历只能进入明确的静态退层。日期来自[年度日历](CALENDAR.md)，记录其校验值、版本和公告重建依据；不代表当时生产日志。所列样本日期是取号区间端点日期，不能当连续日期覆盖或全年代表性。

新加入模式分别排序等待下界和上界，取秩 `ceil(q*n)`，得到 p10/p50/p90 的经验分位数包络。这里采用 [NumPy 官方文档中 inverted_cdf 定义](https://numpy.org/doc/stable/reference/generated/numpy.quantile.html)对应的经验逆分布秩，原创标准库实现，没有引入 NumPy 或复制源码。p10 下界至 p90 上界的跨度没有经过校准，不能声称是具有实际 80% 覆盖率的预测区间。

代表点使用“估计中位数包络的中点”，并明确记录该预测约定；没有把每条经历的时间区间中点冒充精确标签。只有真实后续结果和时间切分回测才能评估误差，见[预测评估](PREDICTION_EVALUATION.md)。

## 已等待模式

将 `mode` 改为 `remaining`，添加精确声明的 `issued_at` 和 `call_not_observed: true`，并必须提供随机 UUID4 的 `target_episode_id`。这些是调用者对自己的过程声明，不从公共前三位推断。已等待时长为 `as_of−issued_at`，要求在 0–48 小时内；匹配日期使用取号时刻，预计叫号时刻由当前时刻加剩余等待构成。

计算条件是总等待 `T>e`，其中 e 为已等待时长。下界大于 e 的样本肯定仍存活；上界大于 e 的样本可能存活。对 t≥e，条件 CDF 下界为“肯定存活且上界≤t 的数量／该数量加上界>t 的数量”；上界为“可能存活且下界≤t 的数量／该数量加下界>t 的数量”。分别反演得到剩余分位数上下界。在 e 处使用可能右极限作为分位数下界，零下界不代表确定立即叫号。

肯定存活样本数不足 `minimum_samples` 时返回缺失，不能把所有模糊样本算作仍排队。该计算只对有限区间样本做经验条件算术，没有建模未叫号结果的右删失，也没有消除只观察到完整经历的选择偏差。测试包含小规模区间的全部离散赋值，核对实际条件分位数被包络包含；这不替代真实预测检验。

## 理想时间模式

将 `mode` 改为 `ideal_time`，添加 `desired_arrival_at`、整数 `call_offset_minutes` 和严格递增的 `candidate_issue_times`（1–288 个）。到店和候选取号时刻均在 as_of 至其后 24 小时内；偏移暂限 −120…120 分钟，目标叫号时刻不得早于 as_of。范围都是研究计算边界，仍未核实实际可取号时段。

目标叫号 `C=A+b`：+10 是希望到店后约等待十分钟，−10 是希望到店前十分钟叫号。逐个候选独立匹配历史，比较估计中位数叫号包络与 C 的最大距离；选距离最小者，相同选较早候选。候选只限调用者给定列表，不假设叫号随取号时间单调，不使用二分搜索，不声称全局最优或可预约。没有足够历史时不生成取号建议。

此选择没有计算真实过号概率、取消代价或门店可操作规则，不能驱动重排。实时模型、跳号波动、防过号、两模式实际误差、授权业务和生产验收继续原完整目标；微信前端仍遵守先真实字段与刷新验收的顺序。

## 复现与继续验收

历史输入指纹仅包含算法策略、规范化计划、截至当时可用且匹配的区间/日期/接收依据及日历版本。完整库审计数量、未来接收与冲突统计放在 `audit_diagnostics_not_features`，不能当预测特征。后续补录未来经历不会改变既有截止时刻的候选或输入指纹，但可能改变审计诊断。

下一步是取得正常真实用餐证据、确定可训练资格、记录实际预测时刻，再按时间划分做基线误差和区间覆盖校准；之后加入当时已接收的实时变化和经过核验的外部事件，比较增益。当前入口输出始终区分研究候选与可供用户安排到店的 ETA。
