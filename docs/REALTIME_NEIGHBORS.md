# 实时邻域等待分布：研究模型与连接

rc53把历史等待分布与实时数值模型连接起来。它从审核过的独立排队经历，学习相近日期、已等时长和展示变化下的剩余等待区间，生成`realtime`候选；与原来的`history`候选按完整CDF融合。真实认证标签仍为0，没有真实准确度、供应商效果或已校准ETA。专项使用明确合成资料，不能作为寿司郎真实误差。

## 为什么先采用这个基线

邻域方法根据与当前输入相近的训练经历预测连续结果；它易于追查选择了哪些资料，适合作为后续AFT、分位数树及AI融合的对照。一般方法见[scikit-learn官方邻域说明](https://scikit-learn.org/stable/modules/neighbors.html)。本项目使用原创标准库实现，保留区间和次数，不复制实现、不引入scikit-learn、不用区间中点训练精确标签。

官方说明提醒：第k和k+1个样本距离相同但标签不同，结果可能依赖输入顺序。本实现把第k距离处的全部并列经历保留。`neighbors`因此是目标邻居数，实际选择可以更多，仍受完整研究资料100行的边界约束。不能为了得到偏好的等待时间挑掉并列经历。

## 资料与模型输入

显式只读三份独立、闲置私有库：首次接收结果、审核声明、封存门店观测；沿用[经历对齐](OUTCOME_FEATURES.md)的完整修订审计、首次接收、成对查询完成和限量规则。活库持有写锁时拒绝读取，工具不终止采集、不复制活库、不自动寻找资料。

每次拟合只使用预测截止之前已接收的结果和审核；目标经历全部排除，门店、资料来源、API profile、队列、人数和桌型精确匹配。后来收到或修改的资料不能进入此前预测。人工确认仍是声明，不能自行升级成认证训练资格。

输入向量为已等微秒、每有效观察分钟移出的展示字符串数，以及可用时的未知单位原始数量。数量缺失和真实0分开；当前缺数量只匹配同样缺数量的历史。自己的票号不作为已认证前方桌数，尚未加入可靠私人位置模型。有限展示变化不是完整推进速度或真实弃号率。

窗口要求至少两对可比较观测、至少50%的有效覆盖；只匹配平均采样间隔处于当前0.8–1.25倍范围的资料。当前失败、过期、保存历史来源或停止的采集状态，实时模型保持缺失。历史有效比较会被失败、缺口和run切换打断；局部有效覆盖不能证明整窗连续或源数据新鲜。

## 每个排队经历只有一份质量

从精细日期分组到同店静态退层，顺序沿用历史基线。每个分组内，同一episode先取最接近当前已等时长的一个历史观测时刻；相同取更早时刻。重复更新不能被当成几十个独立顾客。

从这些独立代表计算各特征的中位绝对偏差；为0时使用观察范围，再使用明确单位。已等时长的单位回退为配置的邻域时差（至少1秒），另外两项为1。距离使用精确分数的标准化绝对差之和，各维还须不超过明确的距离上限；没有支持时退回历史，而非外推漂亮分钟数。参数都是研究选择，未由真实回测调优。

默认至少8个独立经历、目标20个邻居，最大时间偏差300秒，单维标准化距离不超过3。日期／时段实际退层、选择数量、私有选取行、模型输入校验值和参数均保存。排序距离不读取等待结果；已完成且可比较的标签资格、确定仍存活及支持范围筛选当然依赖已知结果，不能声称整个筛选与标签无关。

## 剩余等待如何连续变化

历史观测时的剩余区间若为`[L,U]`、当时已等`a`，当前已等`e`，近邻研究候选使用`[L+a-e,U+a-e]`。只取调整后下界仍严格大于0的经历；在e以前肯定完成或存活不确定的经历不混入这份直接剩余分布。新取号只匹配elapsed=0，不把已等者的剩余时间当作新取号总等待。

这保留了事件区间和连续秒数，但相邻时刻的协变量不是当前精确已等时刻的已认证观测。时间偏差边界是一项局部近似，需要真实回测；事后取号时间上界重建及完成经历选择偏差也仍存在。没有处理右删失、取消竞争事件或未完成者代表性。

融合schema2新增直接条件样本：

```json
{"candidate_id":"realtime","conditional_interval_sample":{
  "conditioned_elapsed_us":300000000,
  "intervals":[[600000000,660000000,2]]
}}
```

这些区间已是剩余等待；按次数计算完整经验CDF，不能再执行`T>e`条件或再减e。旧`interval_sample`继续保存总等待，仍由原算法执行一次生存条件。两类样本必须绑定相同已等时长，追踪提交再核对本人会话。未知上界保持未知，1/3等频仍使用精确分数。

## 与历史及AI怎样组合

`history`来自日期匹配的历史结果，`realtime`来自上述拟合；二者完整CDF按非负权重混合，再反演分位包络。研究默认各50%，这不是调优结论或准确度承诺。缺少实时资料时保留历史；只有实时资料时使用唯一候选。若两份完整CDF包络相同，不添第二个无作用的候选。

公共AI请求只包含既有允许趋势、模型版本和候选ID；训练区间、次数、episode关联、人数、私人取号／用餐时间及票号留本机。既有DeepSeek适配器可对有效的两个不同候选计算有界权重，过期或无效建议回退；默认混合参数0、没有付费调用。本轮合成检查证明权重影响数值，不证明真实API调用、成本或预测收益。

## 私有命令与自动追踪

```sh
sushiwait realtime-fusion-research \
  --source-db private-source/outcomes.sqlite3 \
  --reviews-db private-reviews/reviews.sqlite3 \
  --remote-db private-sealed/remote.sqlite3 \
  --input private-output/target.json \
  --feature-plan private-output/features.json \
  --context-file private-output/context.json \
  --output private-output/research.json
```

目标计划沿用[历史基线](HISTORY_BASELINE.md)的new_join或remaining；观测计划沿用[经历对齐](OUTCOME_FEATURES.md)，截止／来源／店号必须相同、窗口与公共上下文相同。三个库目录分开，目录0700、文件0600；输出新私有文件，不覆盖。仍完整扫描各库最多10000行、观测32MiB、16个landmark和100研究行，输出最多2MiB；超限明确失败，后续需单独扩展长期结果分区。

`ticket-track-run`可显式加`--sealed-remote-db`，需已有`--source-db`和`--reviews-db`。它在真实异步计算线程拟合，再走本人当前版本的原子提交及已有公共AI流程；不额外查询官方。可重复给`--landmark-seconds`指定递增网格，默认0、300、600、1200、1800、2700、3600、5400；可调整`--realtime-window-seconds`（默认1800）、`--realtime-neighbors`和`--realtime-minimum-episodes`。已有日期参考提供窗口时使用该窗口，两侧尺度保持一致；初步真实资料不足仍返回研究冷启动。

## 尚需完成的验收

新模型必须与纯历史、历史加实时、历史加实时加AI在相同时间切分上比较。同一episode全部更新一起划分，不能随机拆行使同一顾客同时进入训练与测试。时间和分组评估问题参考[官方交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)与[TimeSeriesSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)；现有库的首次接收仍需另外约束，不能直接套工具类后宣布消除泄漏。

本轮尚无新的时间顺序真实回测、误差校准、可靠位置、真实快慢情景或模型选择收益。原理想时间全网格、未来实时情景预测、60／30秒防过号、送达提醒、产品页面、全国与正式服务器继续完整目标，没有因这个研究基线而删除。
