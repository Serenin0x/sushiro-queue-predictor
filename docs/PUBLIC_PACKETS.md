# 门店公共字段的本机导出

rc17新增`packet-export`，从明确的私有快照DB2只读选择一页资料，保存到一个新的私有JSON文件。它为后续服务器接收准备数据格式，当前不上传、不提供服务器、不读取查询凭证，也不确认训练标签或等待时间。来源新鲜度保持`unknown`。

## 使用范围

一次明确指定1–3个规范门店ID、一个`api_profile`、一个`data_origin`及带秒和时区的`as-of`；按本机样本ID升序选择1–1000条。只读事务固定本次看到的数据，采集器后来追加的记录留到下一页。选中记录的正文最多64KiB，最终JSON最多4MiB；总内存可能大于最终文件大小，不宣称4MiB是进程内存上限。

POSIX环境要求输入为本人单链接常规文件，0400或0600；输入和输出的直接父目录均为本人已有0700目录。逐级拒绝符号链接，输入不得是目录或设备，输出不得已经存在，不自动创建目录或放宽权限。DB1不迁移、不导出，未知schema拒绝；数据库路径与输出路径相同时停止。读前后检查文件身份，允许同一文件正常追加，拒绝替换或权限变化。SQLite和同账号进程仍有运行环境依赖，不能把这些检查称为对恶意同账号进程的完整隔离。

```sh
sushiwait packet-export \
  --db "$PRIVATE_DATA/samples.sqlite3" \
  --output "$PRIVATE_EXPORT/page-001.json" \
  --store-id 3004 --api-profile miniapp_gateway --data-origin live \
  --as-of 2026-10-06T08:20:00+08:00 --after-id 0 --limit 500
```

`PRIVATE_DATA`和`PRIVATE_EXPORT`是使用者明确准备的私有目录。这个示例不创建文件夹、不启动采集，也不代表可访问任意真实门店。

终端仅输出记录数、本地分页游标、文件字节数/哈希、提交和持久化状态及固定错误类别；不打印门店号码数组、文件路径、请求头或原始错误正文。

## 允许的数据

| 内容 | 处理 |
| --- | --- |
| 门店ID、profile、live/fixture/synthetic | 明确分隔，行与正文必须相符，规范化门店身份须一致 |
| storeStatus | 仅明确OPEN/CLOSED；缺失/null/invalid/unknown保留，未知字符串整页拒绝 |
| groupQueuesCount、raw_wait、waitTimeCounter、waitTimeCap | 保存字段存在状态和整数；单位未知、负值哨兵不解码，缺失不变零 |
| 四类展示号码 | 保留父字段/分组存在状态、顺序和后缀；不是完整队列或全局叫号游标 |
| 号码字符串格式 | 仅窄ASCII字母/数字及一个数字连字符后缀，每组最多64项；不识别的有效字符串整页拒绝，不静默删号 |
| 成功与request/normalization失败 | 保留HTTP请求开始、接收、耗时及固定失败码/HTTP状态；原错误文字不输出 |
| preflight本机保护 | 只记录本机检查时间，不能伪造HTTP响应或源更新时间 |
| 微信头、查询凭证、原始HAR、认证声明详情、个人号单 | 不进入协议对象；地址、名称及任意额外字段也不输出 |

坏的标量类型经既有归一化显示为invalid/unknown和null，仍能保存该字段缺失信息；有效但超出允许格式的号码或状态不会通过。未来时间、重复观测、矛盾身份、异常大正文或无法解析的选中行会使整页失败，游标不会由工具保存或推进。输出内容仍按私有文件保管；字段投影不是上游字段含义或数据共享许可的验收。

## 标识、分页和保存

每条记录的`observation_id`由本机原run UUID、样本ID和范围确定，但原run标识/样本ID不进入协议记录。同一资料在不同导出时刻具有同一观测ID；`record_sha256`对规范化允许内容计算。同ID但内容变化会有不同哈希，以便未来接收器报告冲突。这不是签名、真实性证明或服务端去重实现。

终端的`next_after_id`只针对**同一个数据库和完全相同范围**。确认本地文件完整且持久化后，调用方可以把它用作下一页`after-id`；它不是上传确认，不能用另一个数据库/门店/profile/origin的游标，也不能据此删除源资料。工具没有持久分页游标或待上传表。范围外资料不会推进这个游标。

输出先写入同目录0600临时文件，fsync并读回，再以不覆盖的原子链接公开新名字，移除临时链接后确认目录fsync。已有或并发出现的名字会被拒绝，原文件不改。提交前失败不留下半个目标；提交后故障可能显示`committed=true`但`durability_confirmed=false`，此时不能当作未写入，也不自动回退、覆盖或推进游标。一般异常清理尽力移除临时文件；进程被强行终止、磁盘/系统故障的恢复仍需后续运维实现。

`server_received=false`、`credentials_accessed=false`、`eta_available=false`、`verified_training_labels=0`始终明确。没有上传目的地、网络重试、确认队列或生产服务。

## 后续验收

软件检查覆盖内容白名单、稳定标识、来源分隔、分页/并发、私有权限、已有与竞争目标、提交前后故障以及CLI零网络/凭证/子进程。真实资料导出要另记具体安装包、原库只读校验和导出范围，不用合成检查代替。
