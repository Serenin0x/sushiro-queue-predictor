## 当前数据能回答什么

2026-10-04对明确的项目主数据库做只读盘点，未读取其他资料或发出网络请求：219份成功快照，三店各73份、6个成功采样run；按请求开始时间转换至Asia/Shanghai，10月3日18份、10月4日201份。219份的源更新时间都未知，groupQueues父字段都存在；没有样本带outcome_label，也没有已验收的真实叫号/入座标签。

这219份记录可用于检查字段、请求连续性与展示集合变化，不等于219次独立排队结果。两天都处在2026年国庆放假区间，不能用它们证明普通工作日、普通周末、不同月份或季节的规律。[国务院办公厅通知的北京市政府转载](https://www.beijing.gov.cn/fuwu/bmfw/sy/jrts/202511/t20251104_4258838.html)列明国庆放假为10月1–7日；10月10日虽是周六，却安排上班。日期属性因此不能只用“周一到周五/周六周日”判断。

有限展示号没有覆盖所有排队者，未确认号码规则、队尾或完整事件。因此当前不能从最大号变化计算真实弃号人数、过号率或自己的剩余桌数，也不能把raw_wait直接当作等待分钟标签。

上述219份是10-04当时的指定主库盘点。10-06另有多份独立试验库，按各自软件版本/run/时间单独记录，不改该历史数量或混算成独立排队结果。E0187对其中仍运行的新90轮任务只读回放三店最近20分钟，各20次成功/19可比对、无链断，已出现OPEN与展示变化；当天仍为国庆假期。三个采样日期都不能认证普通周末/工作日或季节趋势，真实标签仍0。

## 三类资料分别保存

| 资料 | 关键内容 | 存储与使用 |
| --- | --- | --- |
| 门店公共观察 | store_id、api_profile、来源、run/sample定位、请求起止、字段状态、完整展示集合、源时间能力 | 继续使用现有schema1快照/DB2；不可变原值，不回填解释或重算旧哈希 |
| 本人排队过程与结果 | 随机episode_id、门店/队列/人数桌型、取号/签到/叫号/过号/取消/入座证据、观测区间 | rc2独立私有人工/合成修订库；真实个人状态API另需授权；公开数据集不包含个人票号、微信身份、联系方式或精确行程关联 |
| 外部日期与事件 | 适用地区、日期、发布日期/当时可获取时间、来源、规则版本、活动/营业调整证据 | 独立版本；不能把后续才知道的活动或结果倒灌为当时可用特征 |

episode_id是随机本机标识，不从微信ID/手机号或原票号生成。本人票号与episode映射若业务追踪确需保存，留在独立私有记录，不能混入公共快照、训练导出或大模型输入。支持多用户前必须另行实现隔离、授权、删除和保留期；当前没有这套账号服务。

## 真实结果的最小记录

同一episode可以有多条事件。每条应包含固定event_type、event_time_lower/upper、observed_at、evidence_kind、verified_scope和revision；不接受任意请求头或原始响应。时间均为带时区时间戳，保存UTC并用Asia/Shanghai解释日期。精确事件上下界相同；两次观察之间发生的事件保留区间，不取中点伪造精确秒数。

| event_type | 所需证据 | 不能推断的内容 |
| --- | --- | --- |
| issued | 本人正常已有号单/已核实业务状态 | 不为制造样本自动取号 |
| checked_in | 已核实本人签到状态或现场确认 | 不以进入门店页面代表签到 |
| called | 本人现场确认或已核实的个人状态事件 | 公共三位出现/消失不自动生成此标签 |
| no_show | 明确本人过号状态或现场可核对事件 | 不把取消、未签到或展示消失混为过号 |
| cancelled | 明确取消结果 | 不用取消时间作为叫号时间 |
| seated | 本人实际入座确认 | 叫号不等于已经开始吃饭 |
| observation_ended | 记录结束时刻和仍未观察到的结果 | 未结束排队保留删失信息，不填零等待 |

evidence_kind先使用有限枚举，如self_observation、verified_personal_status、verified_store_event；后两类接口尚未接入。允许人工输入本人已有正常结果，但需标明观测精度、证据来源与确认范围；不要求截图、手机号或登录凭证上传。人工纠错追加revision并注明被替代事件，不覆盖旧事实。异常时间顺序、跨门店/队列混合、重复或冲突结果进入待处理，不能自动用于训练。

立即取号预测的目标是issued到called的等待分布；已取号追踪的目标是给定预测时刻到called的剩余分布。seated与called分开，理想到店/叫号偏移继续遵守交接文档R04/R05。重排会形成新的episode及私有父子关系，旧episode的取消不变成叫号；重排之后的结果也不能用来声称保留旧号会怎样。

## 日期、时段与实时特征

| 类别 | 第一批候选 | 使用条件 |
| --- | --- | --- |
| 基础时间 | 具体星期、当地日期/时段、月份、小时周期 | 从预测时刻计算；时间戳无时区则拒绝，不默认UTC或北京时间 |
| 日期类型 | 普通工作日、普通周末、放假日期、调休上班、假期第几天 | 使用已核对的年度/地区日历；未知年份保持unknown，不仅按星期或农历推断 |
| 季节与长期趋势 | 月份、日历季节、同店历史趋势 | 日历季节只是时间代理，不代表本店天气或实际客流；当前两天不足以估计长期规律 |
| 公共实时观察 | 有限展示集合的增删/顺序变化、签到计数字段原值与存在状态 | 解释版本独立；数字变化称可观察变化，不包装成真实过号率或全局号码速度 |
| 数据质量 | 请求耗时、最后成功距预测时刻、缺失/失败、缓存提示、采样缺口 | HTTP Date/接收时间不能代替源更新时间；未知新鲜度继续显式保留 |
| 本人信息 | 已取号经过时间、已核实签到、人数/桌型/队列 | 后续仅经业务授权的私有数据路径；公众门店查询不能替代本人状态 |
| 外部事件 | 商场活动、营业临时调整、天气等 | 有来源/适用时段/可获取时间；未核实时不用大模型编造事件或影响系数 |

年度日历按来源公告、适用地区、已核对覆盖区间和版本保存。发布前逐日检查假期、调休和普通日期，年份未知不外推；全国民用放假安排也不是门店营业保证，地方节日和门店特殊安排另存。rc3已实现2026全年日历模块及date-features离线入口，官方来源/核对版本/公告可用边界分开保存，未核对年份保留unknown；见[CALENDAR.md](CALENDAR.md)。没有自动下载服务，也不凭全国日历保证门店营业。

滚动窗口只能用预测当时已经接收的成功数据。失败、无效字段、跨来源/profile/队列、不同run或明显采样缺口会中断可比较链；窗口不足则缺失，不能补零。日内重置、不同号码前缀和预约/堂食不混合。公共展示的变化时间最多位于两次观察之间；若源时间未知，更不能声称这是精确叫号时刻。

## 训练与误差评估的进入条件

1. 固定一次可复现的数据窗口，列出真实/合成来源、门店/日期覆盖、失败/缺口、完整episode数量和删失比例。合成数据用于软件检查，不进入模型成绩或历史规律结论。
2. 每个训练例记录prediction_at、features_available_at、标签证据版本和episode_id。只使用当时可用资料；训练和测试按时间先后且episode不跨集合，禁止同一排队过程的相邻快照泄漏。
3. 先比较可解释历史基线与候选分位数模型。raw_wait单位未知，不可用作真值；取消、未完成和重排偏差分别处理。没有可靠标签时直接报告无法评估，不输出“平均误差±几分钟”。
4. 在另一个时间窗口校准区间，再报告绝对误差分布、覆盖率、区间宽度、日期/门店/时段分组、样本量和删失情况。少量国庆样本不能支持普通周末或全年可信覆盖率。
5. 过号率先确认分子/分母可观察与窗口一致；不足时仅评估有限展示变化指标。通知与真实过号状态的效果另行验收，30秒采样不保证不会过号。
6. LLM仅处理脱敏外部事实/解释，并做加入前后的回测；不接收个人凭证或原号单。取消/重排仍按独立授权和业务规则，不能由文本推断直接触发真实操作。
