# 官方公开观测的服务器同步

当前是本地接收候选，尚未部署或创建SSH访问。首次无人跨声明期限更新见PROJECT_HANDOVER的E0442，传输实现与检查见E0443；两者不等于多天稳定性已经完成。

## 数据流和边界

本机通过既有授权会话取得新码，官方接受后整组更新私有查询上下文；低频采集保存完整公开展示字段。仅严格校验的public packet送至服务器，查询凭证、微信会话、正常初始化材料及官方代码不传过去。服务器独立保存原包与SQLite归档，现有只读月历从归档读取。查看页面不增加寿司郎请求。

新增`sushiwait.ssharchive`作为操作员配置的SSH forced command。独立传输key只能执行固定的`sushiwait-official-packet-v1`；服务器命令和view路径固定，输入不能指定文件路径、脚本或命令。部署时禁止PTY、代理、X11与端口转发，不使用日常管理key。该模块不自动创建用户／key／防火墙规则，也不提供公网HTTP上传路由。

## 接收契约

- stdin最多4MiB、1000条、15秒到EOF；额外私人字段、重复JSON键、非有限数字、内容摘要损坏和范围不一致整批拒绝。
- packet明确store_ids与本机view配置的1–3店完全相同，profile必须miniapp_gateway，origin必须与配置一致；生产配置为live，不与CRM合并。
- 服务器在归档旁预建0700的packets目录，文件按规范公开包SHA命名、0600、不可覆盖。原包核对并fsync后，再通过既有事务归档追加。相同观测去重，内容冲突整批回滚。
- 回执返回包摘要、每个观测ID及记录摘要、插入／去重计数与持久提交状态。发送端仅在SSH正常结束、固定服务器主机公钥校验通过、回执与当前包完全匹配后记确认；超时或回执丢失属于未知，保留包供幂等重传，不删除原数据。
- 回执说明的是该服务器归档已接收，不认证上游新鲜度、真实叫号时间、人数单位或全天连续性。401／403保护和源查询预算不受网页或传输重试改变。

发送端应使用固定argv与BatchMode／IdentitiesOnly／StrictHostKeyChecking=yes，指定独立key及经现有可信云终端核对的known_hosts；不使用shell字符串拼接、accept-new或关闭主机验证。先部署固定版本及公开字段配置，再确认是否创建这个新增受限访问。新的SSH授权需要用户明确同意，不把常规云登录授权推定为新key授权。

## 长期观察和扩店

按用户R57，早期低频筛选持续排队较多的门店，短暂高峰少量排队的店降低优先级。当前三店原五分钟／51槽自然期限试验不改；全国低频筛选在明确新计划、业务时段、全局分散准入和预算之后启动。单位未知保持未知，失败／缺失不算低需求。未来个人临近用餐60／30秒监控是另一阶段的需求。

长期稳定性分开记录供应会话、官方初始化／查询、采集连续性、公共同步、服务器重启读取和跨日开闭店行为。一次到期恢复已经实测；多次续期、跨日与完整多天的结果只能按实际时间积累，不能由模拟测试或一个200推定。当前材料仍仅在本机原审计进程内存，Mac关机／冷启动和独立服务器供应尚未解决；服务器同步只传公开数据，不消除该依赖。
