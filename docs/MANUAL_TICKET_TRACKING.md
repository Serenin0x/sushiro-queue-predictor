# 手动已有号码的私有追踪

rc49新增手动号后台会话、公开观测绑定、条件剩余计算及当前版本原子提交。用户已经在官方客户端取号，本组件保存明确提供的门店、队列和号码；不取号、取消、签到、重排或登录。当前是后台库函数和CLI；rc50另增加[自动更新编排](TICKET_TRACKING_LOOP.md)，没有产品输入页面、提醒送达或已校准ETA。认证真实训练标签仍为0。

## 怎样处理号码

堂食只匹配`storeQueue`、预约只匹配`reservationQueue`，完整保留展示顺序、重复号码与前后缀。不会把另一个队列的号码拿来判断自己。支持当前匿名来源识别的号码格式：一个可选ASCII字母、1–7位数字和可选短横线后缀。

状态区分目前出现在展示列表、曾被本机看到但当前没有、从未被本机看到、当前资料不可用。首次／最近看到的时刻是本机接受那条HTTP响应的时刻，不是实际叫号或首次在上游出现的时刻。列表是有限集合；消失、较大号码出现、重新出现、重复、缺口均不自动转换成已叫号、过号、签到、入座或取消事件。消失后给出核对状态建议，最终状态由本人明确声明。

纯数字且前缀完全相同的标签可保留逐个算术差，前缀不同或带后缀保留未知。差值不是精确前方桌数；没有验证发号周期、排序、每号一桌或完整游标。个人号码及其差值留在私有会话里，不进入公共大模型请求。

## 观测怎样绑定

输入已有写者的门店`queue`投影及[公共上下文](DISTRIBUTION_FUSION.md)，或者先用写者`history`投影整理上下文。门店、队列和截止必须相同；当前成功队列响应时刻必须精确一致，避免分两次读取时把新号码与旧上下文拼在一起。这个检查不证明两个接口是原子上游快照，`read_pair_atomic=false`保持。

最新请求失败后的旧成功、恢复历史、工作者停止、超过本地响应年龄、未来／逆序时间，都不能作为当前展示证据。数量接口单独失败时，不丢掉仍然有效的队列响应。源更新时间、数量单位与门店身份仍未认证。新观测收到时刻不等于上游内容更新时刻；进程内观测版本重置后，只要真实响应时刻前进，私人追踪仍可产生自己的新版本。

正在运行的rc43/rc45真实任务不升级、重启或延长，不能为了新路由读取它们的SQLite。读取者只拿写者投影，额外上游查询为0；本手动组件只读取明确文件或库；rc50独立编排只读同机工作者的固定投影，不追加上游查询。

## 条件等待与AI

取号时刻已知且当前展示资料可用时，将同一私人episode和观测截止传入[历史区间桥接](HISTORY_FUSION.md)，由此排除目标自己的结果、后来接收的经历与审核。所有原始历史区间完整保留，按“尚未叫号”条件重新计算剩余等待，生成研究叫号时间包络。号码本身没有被当成已验证的排位特征，真实位置／快慢模型仍待拟合。

“仍在等待”的依据是用户持续声明，公开有限列表不能认证用户尚未被叫。即使号码消失，也不制造真实完成标签或盲目结束会话；状态需要本人核对。取号时间未知、资料不足、当前投影不可用、上下文到期或超过模型等待支持范围时，研究预测缺失，不补造取号时刻或零等待。

另一种入口接受调用方给定的schema2完整条件区间候选：必须绑定同一公共上下文、私人取号时刻的已等时长和数据来源。不接受已经条件化但无法绑定已等时长的支持点。多情景可配合已通过校验的公共AI权重实际改变区间；只有历史情景时没有额外数值作用。候选拟合、模型真实性、总体误差和覆盖率仍未认证。

CLI可读取明确的公共建议文件；格式坏或无效建议保留本地先验回退，不等待或重试供应商。此入口不调用DeepSeek、不读取模型钥匙、不计费；[有界供应商适配器](DEEPSEEK_ADAPTER.md)独立保留，rc50自动后台可显式连接该适配器，真实多情景拟合和同时间切分的有／无AI检验仍待完成。不能把合成权重当作真实模型输出。

## 60／30秒请求和版本提交

已知理想到店时间时复用原偏移语义与[监控时间策略](MONITORING_TARGETS.md)：前30分钟请求60秒、前15分钟请求30秒，研究较早叫号端只能提前请求。`+10/-10`是用餐偏好，不是预测误差。

即使没有历史分钟数，只要自己的号码曾被当前本机投影看到，当前出现或后来状态不确定时也请求30秒并给出原因。理想到店时刻未知时保持未知；不为取得刷新策略而编造一个用餐时间。结果包括下一目标时刻，rc50可把请求加入专用有期限共享计划，新工作者必须显式接入；当前已有真实任务不修改，也没有提醒送达。编排按门店合并这些请求，并保持原有界任务截止、预算及失败规则；30秒刷新不是防过号保证。

每条观测形成一个私人版本，发布预测须在同一目录锁中重新核对最新观测内容摘要、票据绑定及版本。计算期间允许新观测继续前进；迟到结果连同旧先验回退全部拒绝，用户声明结束也拒绝。单个结果新建、不覆盖；有效数值结果在上下文或AI建议到期后不能新发布，状态读取也明确变为过期。历史数值文件存在不等于当前预测可用。

此原子性只覆盖本组件遵守锁的本地提交；它不是完整HTTP多用户服务、跨机器协调或通知原子性。源内容本身未认证，数值结果始终`eta_available=false`。

## 私有入口

明确准备两个0700目录：输入和空会话目录。文件0600，输入不放在会话目录，不混用凭证、结果／审核库或存活采集库。票据结构如下，示例完全合成：

```json
{
  "schema_version": 1,
  "episode_id": "00000000-0000-4000-8000-000000000001",
  "data_origin": "synthetic",
  "api_profile": "miniapp_gateway",
  "store_id": "900001",
  "queue_type": "ordinary",
  "number": "13",
  "issued_at": null,
  "party_size": null,
  "table_type": "unknown",
  "checked_in": null,
  "created_at": "2026-10-08T10:00:00+08:00",
  "deadline_at": "2026-10-08T22:00:00+08:00",
  "desired_arrival_at": null,
  "call_offset_minutes": 0,
  "minimum_samples": 10,
  "max_updates": 1000
}
```

真实本人输入用`self_reported`，不把合成店号900001用于真实上游。`api_profile`只用于隔离历史结果，不授权或改变匿名门店来源。创建到截止最多24小时，最多2000条观测；已知取号时刻最多早于创建48小时，未知保留null，人数／桌型／签到保留声明与未知。

```sh
sushiwait ticket-track-init --ticket-file inputs/ticket.private.json --state-dir state
sushiwait ticket-track-observe --state-dir state \
  --view-file inputs/view.private.json --context-file inputs/context.private.json \
  --as-of '2026-10-08T10:00:05+08:00'
sushiwait ticket-track-predict --state-dir state --version 1 \
  --source-db source/outcomes.sqlite3 --reviews-db reviews/reviews.sqlite3
sushiwait ticket-track-status --state-dir state
sushiwait ticket-track-end --state-dir state --status ended \
  --declared-at '2026-10-08T10:10:00+08:00'
```

历史两个库只能是闲置的本任务结果与审核库，只读打开。也可显式给`--fusion-plan-file`及可选`--advice-file`，不能和历史库混用；省略历史和候选仍能记录观察及给出资料不足。每次需要传本次实际版本，不自动追赶、生成票据、无限续会话或重复付费。

会话包含不可覆盖的`ticket.json`、顺序`observation-NNNN.json`、相同版本的可选`prediction-NNNN.json`和一次`terminal.json`。结束是本人声明，不取消官方号；不会自动写成已认证用餐结果。正常结果记录继续使用[结果接收](OUTCOME_INTAKE.md)及[审核](OUTCOME_REVIEWS.md)，还需把真实时间和原始证据对应。

输入文件16KiB、单条会话文件64KiB、目录最多两倍观测上限加两文件；超限拒绝、不裁剪。本入口比历史桥接完整输出2MiB上限更紧；如果一条历史审计结果过大，明确写入失败而不是只存几个分位点。目录独占、完整链和文件身份检查拒绝回退、同时间内容冲突、公共权限、链接与未知文件。进程在临时文件写入期间崩溃留下未知文件时会停在待人工核对状态，不删除资料或声称自动恢复。

先同步文件再原子链接提交，同步确认失败时保留`committed=true/durability_confirmed=false`，不撤回、重置版本或称未写。已知内容相同的重复提交先重新同步目录再报告持久化确认。所有标准输出只显示版本与固定状态，不打印号码、私人行程、分布或路径。
