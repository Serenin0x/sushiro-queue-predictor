# 两种预测与误差的实现、验收方案

本文是下一阶段设计，尚非可调用预测模型。当前真实训练标签0、源新鲜度未知，ETA不可用。已有数据契约见[DATASET_DESIGN](DATASET_DESIGN.md)，本人结果工具见[OUTCOMES](OUTCOMES.md)，公共展示分析见[SIGNALS](SIGNALS.md)，完整要求见[PROJECT_HANDOVER](PROJECT_HANDOVER.md)。正常查询更新与营业字段验收仍优先；不以本方案替代v0.2/v1验收。

## 预测目标与用户时间偏好

立即取号模式预测从实际取号到首次有效叫号的等待分布，输出叫号时刻区间及证据状态；已持有号码时预测从现在到叫号的剩余分布。两者不是同一训练目标，不能用所有已排队者的平均剩余时间代表新加入者。

用户输入理想到店时刻A、偏移b分钟，目标叫号时刻C=A+b：+10表示到现场后约等十分钟，-10表示理想到店前十分钟叫号。b是本人偏好，不是统计误差。模型区间、数据误差及目标偏移分别保存/显示。入座、到店和叫号为不同事件，不能把叫号等同开餐。

反向模式在允许取号的候选时刻t上预测叫号分布，按实际可观察信息选择与C接近、同时控制提前过号及迟到用餐代价的时刻。只在单调性有真实依据时使用二分搜索；预约/堂食、放号规则、开闭店或时段跳变可能破坏单调性。对不可达时间或证据不足返回原因，不硬造一个排号时刻。

## 数据进入模型的门槛

- 本人事件格式校验与真实性审核分开。rc2记录目前只能unverified；新增独立审核依据及策略后才可能形成可训练标签，不将导入成功当审核通过。
- 同一门店/profile/队列/人数桌型的可追溯结果独立成episode。取消、重排、返签与二次服务尝试按实际规则分开；取消不补成叫号，旧号的反事实结果不能从重排结果推出来。
- 实时特征以预测当时已经接收的观测为准：展示集合、签到聚合原值/缺失状态、实际采样间隔、失败/缺口和源时间状态。有限前三位不提供完整队尾，也不能计算全体过号人数；raw_wait等单位未核实，不作分钟真值。
- 日期特征使用已核对年度版本及公告当时可获取时间；工作日/普通周末/具体周几/调休/节假日/假期序号、时段、月份/季节分别记录。缺失类别保持未覆盖，不能用国庆资料证明普通周末或全年规律。
- 外部事件需有适用门店/地区、有效时段、来源及可获取时间。LLM输入仅公共白名单资料，不包含本人凭证、票号、微信身份、精确私人行程或结果原文。

## 从基线到候选模型

先实现按店/队列/日型/时段分层的可解释历史基线，明确每个分层的实际样本数、覆盖日期和可用范围。稀疏分层退回较粗层必须标记；没有足够匹配资料时输出缺失，而不是回退虚构的全国平均值。

候选模型分别预测等待分布的分位数，结合滚动实时变化与历史日期特征；已取号剩余等待需要条件在“已等待且尚未有效叫号”这一事实下重新估计。月份/季节特征先作为可检验输入，真实收益由跨时间回测决定，不预设固定影响系数。先保持同一特征/结果版本再对比基线、统计模型和加入LLM事件特征后的模型。

LLM负责把有来源的外部事件整理为受限结构和解释，并输出unknown/不足；它的文本不能直接改号码、取号时间、过号概率或触发取消。输出需验证字段、时间/地区和来源引用；超时、解析失败或资料不足时保留传统模型及资料缺失状态。是否采用其事件特征由同一时间切分的消融评估决定，不能把模型写了一段解释当作改善误差。

## 回测、防泄漏与区间结果

固定一次不可变的数据窗口/版本，训练、校准和测试按真实时间先后切分，同一episode不能跨集合。模型在拟合时只能使用当时已经可获取的训练资料及标签；特征按每次prediction_at重建，后来的叫号/修订/活动不能倒灌。测试使用后续真实结果评估，记录结果尚未完整的删失数量，不把相邻快照随机拆分成独立结果。

标签叫号只知道区间[L,U]时不取中点伪装精确事件。对点预测p，绝对误差下界为到[L,U]的距离，上界为max(|p-L|,|p-U|)；只有L=U才得到单一真实绝对误差。按实际精度报告误差界、样本数和证据来源。未叫号/取消/未观察完成分别说明，不填0或悄悄丢弃后声称高准确率。

对预测区间[P,Q]，一个区间标签完全包含于[P,Q]才能确认覆盖；若[L,U]与[P,Q]不相交则确认未覆盖；部分重叠只能确认“可能覆盖”。汇总覆盖下界为确认覆盖比例，上界为可能覆盖比例，另外报告区间宽度。不能把相交都当命中，或用粗粒度标签包装成秒级误差。右删失结果需要另选与删失相符的评估方法，不能直接混入点误差分母。

分别报告整体及门店/日型/时段/预测提前量的样本数、日期覆盖、误差分布、预测区间宽度、覆盖界和缺失/删失情况。名义置信水平是输出参数，尚未校准时不声称实际达到该水平；不设一个随意样本数量即宣布全国稳定。固定评估版本后才讨论产品验收阈值。

## 防过号与重排的衔接

已实现[单人目标](MONITORING_TARGETS.md)与[同店共享目标](SHARED_MONITORING.md)只输出刷新策略，还没有驱动调度。之后接入真实计划时按到店/目标叫号/较早估计中的更早边界执行前30分钟60秒、前15分钟30秒，同店合并最紧迫周期，缺口不追赶。实际频率和源变化/允许额度单独验收；30秒查询不保证不会过号。

展示快速消失只作为可观察加速信号，引发提前重算或保守提示；没有全体事件时不叫真实过号率。重排需同时估计保留旧号和重新取号的可行区间、取消/新号成功状态、允许规则和操作风险。取消与新取号不能视为原子事务；结果未知时停止重复操作。若新取号预计严重过晚，保留当前号并及时提醒提前到场，不能为了贴近理想时刻盲目取消。

真实通知、取号/取消/重排与个人状态接口仍未实现/授权验收。本轮不执行这些写操作，不为造标签取号。自动决策先做有实际历史证据的离线回放和无副作用建议，再按原需求推进受控业务验收。
