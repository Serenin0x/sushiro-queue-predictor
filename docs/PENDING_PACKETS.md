# 本机持久待确认包

`packet-enqueue`将明确公共字段包保存到本人已有0700专用目录，`pending-status`只读校验这些包并报告聚合数量。二者不联网、读取查询凭证、发送资料、接受服务器确认、删除资料或推进采集游标。当前保存工具保持独立；[本机投递与历史签名确认](PACKET_DELIVERY.md)已实现，远程上传、确认驱动的目录推进与部署仍待完成。

## 保存与重新打开

先按[PUBLIC_PACKETS](PUBLIC_PACKETS.md)导出私有包，再执行：

```sh
sushiwait packet-enqueue --input "$PRIVATE_EXPORT/page-001.json" --directory "$PRIVATE_PENDING"
sushiwait pending-status --directory "$PRIVATE_PENDING"
```

两个目录均由使用者明确准备。待确认目录不能混放数据库、HAR、配置或其他文件；不自动创建目录或调整权限。输入仍遵循[PACKET_ARCHIVE](PACKET_ARCHIVE.md)的字段、规范时间、4MiB/1000记录及私有文件规则，空包不入队。

规范内容SHA及门店/profile/origin范围SHA决定文件名，文件0600、单链接、拒绝符号链接。相同规范包重复加入时检查完整内容，保留已有文件和首次修改时间；新导出时间会形成另一个包，即使其中部分观测相同。因此状态输出`pending_record_occurrences`是各包记录出现次数之和，不能当作唯一观测或训练标签数量。接收器仍需要按观测ID去重。

新文件采用已有完整写入/fsync/读回/无覆盖原子发布流程，容量检查在协作目录独占锁内完成。最多128包，每包最多4MiB；不是无限积压，也不保证进程内存上限。达到容量时保留全部旧包，停止新增，重复包仍可核对；目录超过容量或含不认识的文件时需明确检查，不自动清理。

## 状态与故障

`committed`表示本次文件已经发布，或已确认相同包存在；`durability_confirmed`表示本轮持久化确认完成。提交后的故障不能解释为“未写入”，也不会覆盖或回退文件。重复核对重新确认文件与目录持久化；检查失败保持原内容并输出固定错误类别。

状态读取采用共享协作锁，只校验至多128包及内容SHA/范围/私有权限；读取前后目录变化会停止，不返回部分成功。终端只显示数量、哈希和保存状态，不显示号码、文件路径、原始异常或凭证。

进程强行终止可能留下临时文件。遇到不认识的文件，包括这种临时文件，工具保留它并要求检查；当前未交付自动孤儿文件恢复、备份、网络重试、永久调度或确认后的保留策略。同账号恶意进程和系统/磁盘故障仍是运行环境边界。

`server_received=false`、`source_claims_verified=false`、源新鲜度`unknown`、真实标签0和ETA不可用保持。文件名/校验值不是签名，不认证官方来源。具体版本、安装和真实数据包实测见[PROJECT_HANDOVER](PROJECT_HANDOVER.md)。
