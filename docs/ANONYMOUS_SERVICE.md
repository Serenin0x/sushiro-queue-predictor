# 匿名号码服务：采集过程中读取已保存的展示状态

当前候选0.2.0rc30新增`remote-serve`。这是一个明确预算的本机只读HTTP服务与匿名采集工作者，沿用[匿名任务](ANONYMOUS_TASKS.md)的进度、数据库身份校验和显式恢复；没有无限重启或全天运行验收。正式v0.2/v1、预测、通知和业务操作分别验收。

## 为什么需要这一层

匿名数据库的写入会话持有父目录独占锁，其他进程的只读报告不能同时打开它。服务保留这项保护：只有一个工作者创建、读取和写入SQLite；在成对观测已经保存、任务进度已经确认后，发布经过白名单验证的展示副本。HTTP请求读取副本，不操作SQLite、不查询寿司郎、不接收个人计划、微信凭证或自定义上游地址。同店多个浏览者共用已经取得的观测。

## 安装与运行

基本数据工具仍只用Python3.11+标准库。HTTP运行器是可选安装项，固定`uvicorn==0.53.0`；从仓库安装时可使用`python -m pip install '.[server]'`，发布wheel安装可选择对应`server` extra。未安装时命令返回`remote_service_install_server_extra`，不会启动采集或创建任务。

明确准备一个已经存在、权限0700的私有目录；任务文件、锁和数据库0600，目录不要放在公开仓库或云盘。下面的占位路径须替换为自己准备的私有目录：

```sh
sushiwait remote-serve \
  --db /path/to/private-directory/remote.sqlite3 \
  --task-file /path/to/private-directory/task.json \
  --store-id 3014 \
  --interval 60 --samples 120 --port 8765
```

范围仍为1–3家明确门店、30–3600秒、每店1–120轮；每个槽位最多两次GET，首个失败保存后停止采集。`--samples`是每店目标轮次，服务总预算最多为门店数×轮次×2，不是HTTP读取页面的次数。未开始的新轮次可被正常退出中止；已经开始的一对查询允许按各自15秒超时完成和保存，然后不开始下一店/下一轮。

恢复必须显式添加`--resume-task`，数据库、门店顺序、周期、目标轮次与原任务一致。原预算不重置，已经保存的结果不重复查询，未确认的槽位留作未知缺口；恢复未完成任务先等待完整周期，不补发积压。完成/失败任务只提供已保存状态，不创建新的匿名查询客户端。正常退出后剩余任务可以显式恢复，进程存活和最后公布的任务进度分别显示。

命令默认绑定127.0.0.1，端口1024–65535；rc34容器桥接可显式listen-host0.0.0.0，宿主回环发布和边界见[Linux部署](LINUX_DEPLOYMENT.md)。单个HTTP进程、一个工作者、lifespan开启、访问日志关闭，不接受代理头配置。由进程管理器自动重启和远程HTTPS入口均尚未交付。更大预算、持久60/30秒共享计划、24/72小时调度需要后续独立实现，不以反复生成短任务代替。

## 只读接口

| 路径 | 内容 | 含义 |
| --- | --- | --- |
| `GET /api/v1/stores/3014/queue` | 明确范围内门店的五类数组和未知单位数量，各自最近尝试与成功响应年龄 | HTTP读取本身不触发采集，号码不是全局叫号游标 |
| `GET /api/v1/status` | 实际工作者存活、服务状态及最后公布的任务检查点 | 公布进度可能落后于正在进行的请求；不输出私有路径、内容校验值或个人计划 |
| `GET /health` | 采集工作者运行状态 | 运行中且工作者存活为200，其他为503；这是采集工作者活性，不是源新鲜度或预测可用性 |

仅GET；未知门店/路径404，其他方法405，查询参数或请求体400。固定JSON响应，`Cache-Control: no-store`。不提供取号、取消、重排、微信登录、订阅或数据写入接口。HTTP服务可以在采集预算完成后继续响应，此时健康状态503、号码明确为旧信息；HTTP端口仍存在不能视为持续取数。

## 展示状态契约

`fields.groupqueues`与`fields.storequeuecount`分别携带`payload`、`received_at`、`response_age_seconds`和`latest_attempt`。五个数组完整保留顺序、重复与后缀；数量保留`raw_count`和`unit=unknown`，不转换为签到桌数、分钟或人数。两次GET非原子快照。

| state | 可以表达的事实 |
| --- | --- |
| `unavailable` | 尚无可用成功响应；payload为null，不能显示为空队列或零等待 |
| `recent_response` | 运行中工作者已经保存成功响应，本机年龄未超过阈值；上游新鲜度仍unknown |
| `stale_response` | 成功响应的本机年龄超过阈值 |
| `last_known_only` | 最新查询失败/被跳过，或采集已停止/结束；保留上次成功数据并说明原因 |
| `saved_history` | 本进程启动时从历史库恢复的数据；工作者启动不会让它自动变为新响应 |
| `clock_invalid` | 已保存成功响应时间位于当前时钟之后，年龄不可用 |

数量查询失败时，队列查询的新成功可以显示`recent_response`，原数量单独标`last_known_only`。队列查询失败会跳过数量查询，两项分别显示最近尝试与旧信息。默认阈值是max(120秒,2×周期)，`--stale-after`可明确指定30–7200秒；它不是对寿司郎源刷新速度的保证。

来源身份、源更新时间、源延迟、数量单位和完整叫号游标仍未认证。所有结果保留`source_freshness=unknown`、`eta_available=false`、`verified_training_labels=0`。启动恢复每店最多检查最近1000行，超出窗口的成功不补造；完整固定任务结果仍由原任务对账机制校验。

## 验证与后续小程序

软件检查覆盖实际数据库锁下读取、副本不被调用方修改、独立数量失败、陈旧/未来时刻、历史恢复、原预算、重复启动、在途退出、lifespan和无写入路由。隔离安装的合成ASGI检查不访问真实门店，真实HTTP与上游查询另行记录在交接历史。

下一步将此只读契约用于SUSHIWAIT自己的微信小程序。服务器承担采集、历史和预测，小程序负责门店选择、号码与状态展示，之后接两种预测与提醒。用户询问部署可能性后，当前仍按原R18先数据再前端：先完成服务联动及字段契约，再搭首版真实号码页面；当前尚无小程序账号、AppID、HTTPS入口或上线审核结果。微信网络与订阅文档本轮直接读取失败，平台具体要求须届时用可读官方资料核验，不能保证订阅频率或上架结果。

HTTP层遵循[ASGI lifespan规范](https://asgi.readthedocs.io/en/latest/specs/lifespan.html)的启动/退出事件，显式失败时不假报启动完成；[Uvicorn lifespan说明](https://uvicorn.dev/concepts/lifespan/)指出每个worker各自初始化，故保持单工作者并以任务/数据库锁阻止第二实例。可选依赖版本及许可核对见[PyPI 0.53.0](https://pypi.org/project/uvicorn/0.53.0/)，不是对它为最新版本的声明。配置参考[官方设置](https://uvicorn.dev/settings/)，实际安装版本的联动验证单独记录。

后续继续持久共享调度、真正长时窗口、实际服务器和跨日期质量，再取得可追溯叫号结果及误差评估；原两种预测、偏移、防过号和异常加速、LLM、前端与授权自动操作需求没有缩小。完整背景、版本和逐次操作见[PROJECT_HANDOVER.md](PROJECT_HANDOVER.md)。
