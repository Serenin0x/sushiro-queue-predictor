# 匿名采集进度与中断恢复

rc29增加`remote-collect --task-file/--resume-task`和只读`remote-task-status`。它将已完成的匿名成对查询与未知尝试分别记录，明确恢复同一有界任务；不读取微信凭证，不安装常驻进程，不补发过去的查询。原`remote-monitor`的同店60/30秒策略仍是进程内调度，本功能只接固定周期的`remote-collect`。

## 固定范围与私有文件

沿用1–3家明确门店、30–3600秒周期、每店1–120轮；一个槽位为一次门店的成对查询，最多两个GET。配置、门店顺序、数据库路径、周期与目标轮数在任务中固定。重启不会重置总预算，未知槽位也占用原计划位置；有实际请求失败的任务保持失败，显式恢复仅报告，不再查询。

任务schema1的JSON最多16KiB，与匿名数据库schema1的`remote_samples`分开；不能使用旧认证快照库、旧认证任务或个人结果库。现有父目录0700、任务/数据库/空锁文件0600、本人所有、单链接常规文件；拒绝符号链接、被替换的文件和配置冲突，不自动修复权限。

任务含本机路径、文件身份、run标识和滚动结果校验，仍须私有保存，不提交GitHub、不传LLM。任务锁文件防止合作进程同时运行同一任务，结束后保留；数据库写锁防止同一私有目录里的并行写入。不同数据库之间的全国调度/全局去重未实现，不为同一门店同时另开重复采样。

## 创建、恢复与查看

以下是假设已存在的私有目录示例，不是公开服务器或真实门店授权。门店ID须先由正常官方目录核对。

```sh
sushiwait remote-collect --db /private/runtime/remote.sqlite3 \
  --store-id 3004 --store-id 3014 --store-id 2009 \
  --interval 60 --samples 120 --task-file /private/runtime/trial.task.json

# 恢复须重用完全相同的配置，额外加 --resume-task。
sushiwait remote-collect --db /private/runtime/remote.sqlite3 \
  --store-id 3004 --store-id 3014 --store-id 2009 \
  --interval 60 --samples 120 --task-file /private/runtime/trial.task.json --resume-task

sushiwait remote-task-status --task-file /private/runtime/trial.task.json
```

已有任务不加恢复标志会拒绝；缺失任务或缺失/被替换的配套库也拒绝，不新建库替代。恢复后先等一个完整周期，包括上轮剩余门店，再从当前时刻继续；不追赶停机期间的槽位。每次进程使用新run，停止期间最后一个缺口保留，不能把不同run之间的号码变化当连续真实事件。

完成任务再次恢复只核对结果并报告；包含未知槽位时退出1，不能说全成功。发生请求失败的任务保持失败/退出1，恢复不会跳过失败后继续查询，也不自动换来源、更新凭证或重试。需要新试验时显式创建不同任务，不能把新任务成绩拼成原任务无缝运行。

## 写前记录与中断对账

每次GET前，先原子保存槽位、当前数据库run、已有记录边界及开始时间。数据提交SQLite后，再推进任务进度。

- 数据已提交、进度未推进：同一run、门店及边界后的唯一结果只计一次，不重新请求。
- 有尝试记录、没有结果：把这一槽位计为未知，保留缺口；可能发生的HTTP数量为unknown，不能假定请求未发生。
- 多份结果、错误run/门店、历史任务结果被修改、文件身份变化或时钟回拨：停止，不猜进度。

恢复核对任务所有已提交记录的滚动校验，最多360条；不仅检查最后一条。任务前已有数据库内容不作为本任务成绩。实际保存的HTTP尝试数与未知请求分开，最多请求预算仍为目标槽位的两倍。

写任务采用同目录临时文件、文件fsync、原子替换和目录fsync。提交前磁盘失败保留旧进度并停止；替换后的持久化确认失败明确返回`remote_task_durability_unconfirmed`，不回退已提交文件。恢复时依据实际任务与数据库对账，未知结果不会补造。

`remote-task-status`只读任务，不联网、不改库，也不检查进程是否仍存活。`state=running`表示有已保存尝试；进程存活、门店源新鲜度和未知请求数量须分别理解。摘要不输出私有路径、哈希、文件身份、原始队列或run标识。

软件检查包含中断、实际子进程突然退出、磁盘写入失败、旧结果改动、文件替换、同任务并发及多店恢复节奏；合成检查不是生产验收。最终安装与真实中断试验见[交接文档](PROJECT_HANDOVER.md)最新历史；接口与字段边界见[匿名来源](ANONYMOUS_QUEUES.md)，全天/多日、服务器与原完整v1目标见[长期采集方案](LONG_TERM_COLLECTION.md)。
