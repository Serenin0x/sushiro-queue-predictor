# 逐号发放时刻：后置接口研究

2026-10-09，用户明确：继续研究，**不在v1.0部署逐号发放时间功能**。这是后续能力，不是当前0.2采集或核心v1的前置条件。

## 已知和未知

当前匿名来源提供有限展示号码和原始数量，没有每号发放时刻。本人已提供官方正常门店详情的顶层字段也未见逐号发放日志；此结论只适用于这份响应，不能证明官方没有其他接口。没有请求新出票、取消或重排，也没有扫描其他人的号单。

已有本人号码的剩余时间参考可以利用当前和历史展示推进；取号时间有助于区分轮次及总等待。预测“现在取号”还需知道当前发号位置。精确每号发放时间必须有上游合法提供的创建事件／历史查询／官方数据合作，不能从两次轮询之间的号码差精确还原。

## 后续技术路线

1. 核对正常本人取号、自己的号单查询响应中是否提供创建时间、时区、号段／日期／桌型和店号。只使用明确授权的本人正常行为，不反复出票制造样本。只显示客户端本地时间时，分别保存本地提交／接收界限，不冒充服务器时刻。
2. 若正常公开查询提供最新发号位置，可低频保存位置变化与采样时间，估计发放强度；只给新号落在两个观测时刻之间的区间。多个号同时增长时，每个号仍是区间，不线性补出精确时刻。
3. 若需全部号码的精确时间，优先获取官方允许的逐号事件、查询服务或导出。数据契约保留store_id、业务日期、队列／桌型、原号、issued_at、来源时区、响应接收时间、证据等级及修订版本。数字差不是已签到前方桌数。
4. 模型分别比较仅展示趋势、加入发号前沿、加入本人取号时间、加入真实签到／叫号结果的收益。按时间顺序回测，禁止使用预测发布之后才得到的字段；间隔删失资料保留上下界，不自动变成精确训练标签。

## 实施条件

来源与授权明确、字段语义确认、日期和号段一致、正常更新路径可持续，才接入后续版本。原始个人业务信息保持私有，不进入公开GitHub、公共统计页或大模型；公开研究仅保存接口类别和字段语义。当前不承诺可以精确获得全店每个号的发放时刻。
