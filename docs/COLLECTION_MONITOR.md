## 使用

安装 `server` 可选依赖，沿用 `remote-serve`、`remote-window-serve` 或 `remote-campaign-serve` 的正常明确配置。服务启动后访问 `http://127.0.0.1:8765/monitor`。没有数据时显示空状态；完成、失败或停止后保留历史，不自动新建采集任务。

```sh
docker compose -f deploy/compose.yaml build
docker compose -f deploy/compose.yaml up -d
curl http://127.0.0.1:8765/api/v1/stores/3004/history
```

Compose 仍只发布回环端口；在云主机可通过自己的 SSH 隧道查看。选择云服务器之后，先核指定出口能否查询、24／72 小时质量和存储恢复，再做正式访问配置。已有托管 Linux 三店 6 次真实查询的成功不能保证任意新主机长期成功。目前未租用或部署生产服务器。

## 曲线含义

| 曲线 | 纵轴 | 时间与缺失规则 |
| --- | --- | --- |
| 门店返回数量 | `storequeuecount` 原始数量，单位 unknown | 使用该响应自己的接收时刻；失败不填 0，不称等待分钟／现场桌数 |
| 堂食展示变化 | 相邻有效 `storeQueue` 集合中消失的不同号码数 | 重复展示值去重；仅有限展示周转，不称过号人数、速度或真实过号率 |
| 预约展示变化 | `reservationQueue` 的同类指标 | 和堂食分开；失败、非正间隔或较长缺口不产生比较 |
| 成功响应间隔 | 前后有效 `groupqueues` 响应的接收间隔秒数 | 较长间隔保留数值，曲线不跨缺口连接；失败打断比较 |

两条门店查询不原子，保留各自开始／接收时刻、成功／失败／未查询状态。比较的最长间隔使用明确的 `stale_after_seconds`（默认至少 120 秒或背景周期的两倍）；这是展示比较规则，不是认证连续性、源更新频率或无过号。

每店在内存中最多保留 **360 组**已提交观测，只返回允许的统计字段，不返回传输头、个人信息、文件路径或原凭证。重复发布完全相同的查询记录不增加点。移出点数仅统计当前进程，不表示所有历史大小；重启由所属写者按既有有界恢复规则重建，`saved_history` 明示来源。完整原始数据仍在私有 SQLite 中，不能让页面绕过写者锁打开运行库。

## 接口与更新

- `GET /monitor`、`/monitor.js`、`/monitor.css`：包内静态资产，没有 CDN、外部字体或第三方统计；CSP 限制为同源。
- `GET /api/v1/status`、`/api/v1/stores/{id}/queue`：保留既有状态与最新成功副本。
- `GET /api/v1/stores/{id}/history`：返回有界统计历史、保留／移出数量、工作者状态及 unknown 源语义。

页面每 5 秒读取上述本地接口，单次 8 秒读取超时；没有重叠刷新，也不增加官方上游请求。可以暂停页面更新或手动刷新；采集自然终态后停止定时读取。读取失败时旧曲线仍在，标为历史且当前运行状态未知，不能因窗口缩放重新标新鲜。浏览器时间或未来响应异常不补成有效曲线。

源新鲜度、门店返回身份和 count 单位继续未认证。零原始数量与“没有等待”“无需等候”不是一件事。前方已发号位置和已签到桌数的预测规则见核心范围；本统计页尚不计算它们。

当前新增 16 项专项检查（含 Node 运行实际页面脚本），统计与旧服务合计 38 项、完整 1200 项本机检查通过。首次脚本测试因测试夹具在拒绝跨店响应后仍读取未创建的画布失败，修正夹具后通过，页面跨店拒绝策略保留。安装、浏览器和生产环境的后续证据以[逐次交接记录](PROJECT_HANDOVER.md)为准，不把软件检查当作真实服务器上线。

实际本机安装／镜像与西单3组6GET浏览器验证见E0290；临时验证页面已在预定期限结束后清理，不是自动长期服务。当前三日后台任务与该页面是两个独立任务，原三日开机联网时继续，截止后自然结束；合盖休眠／断网不能认证连续采集。长期运行需要显式的有限服务配置与实际部署，不能反复重建绕过预算。

rc46已实现[实时公共特征与候选分布融合](DISTRIBUTION_FUSION.md)，只读摘要不额外查询上游；尚未连接供应商、历史模型候选生成或在线ETA发布，实际验证以交接记录为准。
