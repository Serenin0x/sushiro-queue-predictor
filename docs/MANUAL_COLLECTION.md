# 手动获取门店观测

工程页门店监测总览的“获取全部门店”针对当前已启用的五城83店，不随城市筛选缩小；单店页的“获取当前门店”只针对所选已启用门店。营业外、共享保护暂停或门店隔离时不绕过保护。历史日期上的按钮获取今天的新观测，不回填历史。

首次操作使用本人现有管理密码确认。密码只发送至原HTTPS服务器，再由固定回环登录路径核验，不保存或发给模型；浏览器只取得专用的HttpOnly、Secure、SameSite=Strict采集会话，不能访问微信管理台或更新凭证。默认浏览器会话，勾选“7天内免输密码”才持久保存，服务器最长7天；退出仅撤销采集会话，不取消已提交任务。此功能不要求重新扫微信。

## 调度与保存

- 网页POST只写独立私有请求队列；GET统计、刷新网页、切日期均不发门店查询。仅现有official_fleet_collect进程执行，沿原Fleet.reserve／observe／reconcile保存原始观测和失败，再由原同步及增量读库进入工程页与主日历。
- 一次一个请求在途，calendar-meal-peaks-v1实际开始至少间隔1.4秒，旧策略仍完成后等2.1秒。全店逐个处理，不创建并行采集器或追赶突发。
- 同一请求ID幂等，全店任务可合并单店重复点击；已有不同单店任务时不再排第二个。任务完成后短时重复操作返回明确提示。进度区分保存、失败、跳过和统计同步中；保存完成后有界等待公共索引追上实际请求时刻，旧统计不冒充已同步。
- 仍用原每日／逐店普通查询上限。先按平滑采样相位估算剩余自动采样需求，仅余量足够时提前取样；不足则等待下一次计划观测并合并结果，避免手动操作消耗掉后续自动采集容量。不修改原计划、旧消耗、失败、隔离或更新额度。
- 单店故障继续原隔离政策，其他店继续；429共享退避仍保持。重启后从原始库确认已提交结果，不重复发来源GET；未知预留仍由原全局保护处理。任务30分钟过期，闭店／采集暂停会完成为已保存部分及明确跳过原因，不跨日偷偷重发。

## 接线

`sushiwait.manualcollection`提供独立私有SQLite队列与专用会话。原网关可选`--manual-collection-config`，原采集根可选`manual-collection.json`；未配置时原功能不变，按钮不展示。配置仅含schema、队列绝对路径及现有管理用户名，没有密码、微信材料或查询凭证；目录0700、数据库和配置0600。网关只增加对专用队列目录的写入权，原只读统计与本人记录权限保持。

单一HTTPS POST `/api/v1/collection/manual`接受login／logout／status／request四个固定动作，严格同源、固定结构和有界正文；只有现有管理密码验证后才可提交任务。登录尝试在联系管理台之前持久计数，5次／来源及10次全局每15分钟，失败和超时不免计。专用会话仅存SHA-256摘要。源查询仍只允许cityscope明确范围，不接受任意店号、URL、文件路径、日期或凭证。
