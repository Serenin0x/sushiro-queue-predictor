## 原创接入代码

[initialization.py](../src/sushiwait/initialization.py)提供 `prepare_consumer` 与 `initialize_from_yyb`。供应调用仍由[yyb.py](../src/sushiwait/yyb.py)完成，新增预期应用身份校验，防止准备之后参考文件换成另一个应用。

新增 `prepare_consumer_for_target` 与 `initialize_for_target_from_yyb` 接受必填的 `expected_app_id`，以schema2私有供应配置的目标做独立匹配；无需旧参考文件。两种入口共享原来的单次请求实现和全部材料校验，目标明确不代替正常材料来源。新入口不写查询上下文，当前原子续期验证仍要求既有完整基线。

准备方必须提供两个显式回调：

- `prepare_request(code, utc_second)`：以新码和当下秒级时间，返回完整请求体与五个头。设备、版本、启动参数、签名与日期相关头必须有正常来源证据；本模块不提供官方常量、签名实现、设备身份或版本默认值。
- `accept_session(token, headers)`：接收新业务凭证及不可变头映射，继续独立门店查询。不会收到初始化正文或登录码，仍需另验六头同源、实际 GET 接受与声明保护；模块不自动写入运行上下文。

请求体严格限此前正常流程证实的 `long_token/js_code/ts/nonce/sign/device_id/app_version`；五头为明确提供的 `X-App-Client/X-App-Code/User-Agent/Referer/Content-Type`。这属于实验接口的材料约束，不能推断每一项都是官方必需参数，也不能把五头匹配当成业务查询已接受。

只向固定 `https://sapi.sushiro.com.cn/api/1.3/initialize` 发一次 POST，严格按准备方明确提供的 Content-Type 编码为 JSON 或表单，不猜实际正常客户端使用哪一种，也不据此称官方接受两种格式。默认 TLS 验证、禁用环境代理与重定向，不发送旧授权、Cookie 或任意 URL。新码必须精确进入请求体，应用身份与正常参考一致；本机设置准备后五秒的材料时效保护，不把该时间当成官方容差。单个 consumer 即使失败也不能再次使用；并发调用只允许一份进入请求。

响应必须为同源 HTTP200 JSON，最多 64KiB，拒绝重复键与非有限数字，读取 `data.auth_token`，采用现有完整上下文的8192字符上限，不猜固定 JWT 期限。HTTP401、403、其他失败、传输／正文／验证失败分别给固定安全类别；403立即停止，不换出口或重试。初始化失败的类别能穿过组合链路保留，不被误记成供应端没有返回 code。异常正文、请求头、code、token和原始异常链不输出。

一次供应 HTTP 请求不保证第三方服务只进行一次上游操作：锁定 YYB 的 `invokeWXApp` 源码包含有限的会话恢复后再调用。本项目没有增加外层重试，也没有把这项作者内部行为记为本项目已经验证的自动续期。
