# 历史区间到候选分布

rc48新增私有历史候选桥接和精确经验CDF融合。根据预测当时已接收的结果与审核，按同店、队列、人数桌型和日期选择经历，完整保留等待区间及出现次数，生成可直接交给融合组件的研究计划。支持初始总等待、已等待后的条件剩余和调用方给定的理想时间候选。当前真实认证结果仍为0，`eta_available=false`；不是已训练的生产预测。

目前从历史资料生成的是`history`情景，尚未拟合常态／较快／较慢的实时模型。单一情景的权重必然为1，DeepSeek适配器因此跳过这种无数值作用的付费请求；不会为了演示AI参与而虚构其他三个模型。两种以上有效情景的受限AI权重仍能在新CDF接口中参与融合，专项用明确合成资料验证这条路径。后续继续建立实时候选、私有号码跟踪、正常叫号结果和误差校准。

## 历史如何进入计算

输入沿用[历史基线](HISTORY_BASELINE.md)的私有计划，以及[公共实时上下文](DISTRIBUTION_FUSION.md)。门店、队列和资料截止必须一致。结果库和审核库均只读，由既有接收账本核此前可用的修订和审核；后补录、后审核、冲突、目标自身经历、不同店／profile／来源／队列／人数／桌型都按既有规则隔离。

继续尝试精细日型、时段、星期、月份和季节，到较粗日期，再到同店同队列静态历史四层。实际退层与匹配量保留。最低样本数是操作边界，不是准确度保证；剩余等待还要求足够“确定尚未完成”的历史样本。没有足够资料时，候选为缺失，既不填零，也不自动引入未经校准的全国平均数。

历史等待为取号与叫号两个事件区间的差，保留上下界。相同区间合并成整数次数；三条相同经历仍有三条的频率，不是去重后只算一次。不同区间不压成中点或三个分位点。本组件最多128种区间、合计10000个样本；超过上限报明确错误，不截取最近几条冒充完整历史。现阶段使用审核过的完成叫号声明，尚未纠正只看到完成经历的选择偏差、右删失或取消竞争事件。

## 融合计划schema 2

原schema 1、原策略与概率支持点格式继续可读。新schema 2使用不同策略`public_empirical_interval_cdf_mixture_v2`，允许候选包含`interval_sample`：

```json
{
  "candidate_id": "history",
  "interval_sample": {
    "elapsed_us": null,
    "intervals": [[100, 200, 1], [300, 400, 2]]
  }
}
```

每行是等待下界微秒、上界微秒和出现次数。上界null保持未知；这种支持不等于已拟合删失模型。总等待的elapsed为null；剩余等待必须给非负已等时长，并使用`call_not_observed_after_elapsed`条件。不同情景的已等时长必须一致。与已条件化的外部概率支持点混合时，调用方仍须确保那些支持点对应同一剩余等待目标。

权重仍为非负整数百万分之一，但经验样本的次数比例用精确分数计算。三条等频经历就是各1/3，不通过凑成整数百万分之一来改变秩。对于总等待，CDF下界统计“上界已经不超过t”的样本，CDF上界统计“下界已经不超过t”的样本；分别除以总次数。

对于已等e但尚未叫号，条件是T>e。在总时间t≥e处，令A为确定存活且上界≤t的次数，B为可能晚于t的次数，C为可能存活且下界≤t的次数，D为确定晚于t的次数，得到CDF界A/(A+B)和C/(C+D)。跨过e的区间是否仍存活不确定，因此不能固定一个存活人数或直接减掉已等时间。e处上界使用可能右极限，反演得到的零下界只是最早等待的下确界，不是确定立即叫号。

所有候选的CDF下／上界按有效权重分别混合，然后反演求p10／p50／p90的等待包络；不平均候选中位数。有限点无法确定上界时继续返回null。整个计算保留精确分数，不声称这些区间具有80%或90%的总体覆盖率。

## 两种预测模式和理想时间

新取号模式使用当前资料截止选择历史总等待。剩余模式按本人声明的取号时刻计算已等时长，完整总等待区间留在计划中，由融合入口执行条件计算，不二次减时间；`call_not_observed`仍是调用方声明，不从公开前三位推断。

理想时间模式保留已有符号：目标叫号为到店时间加偏移，+10希望到店后约十分钟叫号，−10希望到店前十分钟叫号。对调用方给出的每个取号时刻分别匹配历史并生成计划，比较中位数叫号包络至目标的最坏距离，相同选较早候选。所有候选都保留缺失和退层，不假定预测随取号时刻单调，也不称为全局最优或可取号时段。未来候选使用截止当时的资料，不读取未来队列。

当前理想时间排序是历史单情景研究结果，不是实时多模型融合后的生产建议；后续需要对各候选完整情景融合、成本与提前风险重新检验，不能悄悄只算历史排名第一项。正常取号、取消和重排没有发生。

## 私有入口

```sh
sushiwait history-fusion-research \
  --source-db source/outcomes.sqlite3 --reviews-db reviews/reviews.sqlite3 \
  --input plan.private.json --context-file context.private.json \
  --output output/history-fusion.private.json
```

目录0700、文件0600，源与审核库目录分开、输出另存，不覆盖原文件；只使用闲置的本任务结果与审核库，不读取正在采集的门店SQLite。上下文可以由写者只读投影整理，旧运行服务不因新源码自动得到路由。没有网络、凭证或模型访问；模型版本和研究AI混合参数可显式设置，默认混合参数0。本组件仅生成历史情景，当前即使改变参数也不能给单一权重制造额外数值作用。

输出保留完整候选融合计划、历史输入摘要、条件、退层及审核诊断，最多2MiB；超限明确失败、不裁剪。输入基线和公共上下文各按既有16KiB边界校验。源／审核首次接收时刻、模型真实性与事件真实性分别记录，人工接受不升级成认证训练标签。完整本地计划和历史频率不会进入`public_request()`或供应商请求。

每个非空`candidates[].fusion_plan`可交给`fusion-research`或相应库函数，计算新的区间结果；公共摘要与AI绑定继续沿用校验和过期回退。真实号码追踪与在线原子发布仍需继续接入，研究文件不是用户可依赖的到店ETA。
