# 匿名展示集合的日期与响应窗口分析

开发候选0.2.0rc32新增`remote-signal-report`，面向[匿名CRM独立库](ANONYMOUS_QUEUES.md)。旧`signal-report`继续用于原Store来源，不能混库。新工具只读已保存记录，输出五类有限展示集合变化、独立数量变化、覆盖与日期属性；不是实际叫号速度、真实过号率、ETA或通知判断。实现与验证见[交接记录](PROJECT_HANDOVER.md)。

## 使用

```sh
sushiwait remote-signal-report --db /private/tmp/queue-observations/remote.sqlite3 \
  --store-id 3014 --as-of 2026-10-06T10:00:00Z \
  --window 120 --max-gap 90 --limit 10000
```

门店与分析时刻必须明确。窗口30–3600秒、最大相邻缺口1–3600秒、最近记录上限1–10000。背景300秒采样不能认证两分钟变化；若分析背景历史，应明确使用较长窗口和相容的缺口阈值，不把稀疏数据插成30秒观测。路径仅为操作者自备私有目录示例，不是已部署数据。

使用独立`RemoteStore(read_only=True)`，单个SQLite读取事务同时取得总行数和有界记录，结束回滚只读事务。它不创建客户端、不读凭证、不联网、不写库或迁移旧来源。正在采集的数据库仍受父目录保护，不能另连绕过；需要等待任务结束或后续在唯一工作者内发布分析副本。本版没有修改正在运行的rc31窗口或增加上游请求。

## 两条响应独立处理

先重新验证整份记录、门店、成功标志、规范run UUID和payload上限，不将损坏行当空数组。只有成对查询的最后一条响应结束时间不晚于`as_of`，才允许整份记录进入窗口；数量请求跳过时用队列查询的结束时刻确定该记录边界。这样不提前使用尚未接收的第二条响应。

队列与数量各自使用自己的响应结束时刻、实际开始时刻和失败状态。数量查询失败时仍可以分析该记录中合法的队列响应；队列失败导致数量未查询时，两路分别标为失败与跳过，不能默认为0。两条请求不是原子快照，数量变化不会与号码变化拼成一个同步事件。

每个端点在失败、run改变、超过指定缺口、非递增时间或请求重叠处断开比较。合法空数组可以得到观测到的零变化；没有可比记录则返回null速率。统计实际覆盖秒数与窗口比例；重复标签和顺序变化保存为值变化，集合新增/移除按去重标签计算，不解析号码前缀、数值、后缀或最大值为人数和进度。

五类数组各给整窗、前半窗与后半窗的集合变化统计。跨中点的间隔只计整窗，不分摊虚构事件；每半至少两对才比较移除标签速率。零基线保持null比值，失败/陈旧/资料不足明确状态，描述性比值不触发“快速过号”告警。数量只给自己的可比对数、覆盖和有符号差值之和，单位仍unknown，不换算为桌数、分钟或客流。

## 历史与日期边界

时间选择基于本机记录的响应结束时刻重建。现有匿名库没有首次提交接收账本，所以`historical_availability_verified=false`；不能用响应时间证明数据库当时已经保存，不能把这份报告当已审核训练集。没有源更新时间、可核验门店身份或完整叫号游标，上游新鲜度一直unknown。

rc33补充[本机首次接收](ANONYMOUS_INTAKE.md)：新写入的观测另存本机事务内接收时刻，`--availability-basis local-first-receipt`额外排除截止之后才收到的记录；旧行缺失接收时刻时保留未知并断链。默认仍是响应时刻重建。接收时刻读取于提交前，不能认证历史持久可用，因此上段的验证false保持；实际变化间隔继续使用两条响应各自的时钟。

扫描先选该门店最近记录ID，再按成对响应时刻过滤。未来记录可能挤出较早历史；上限截断且出现未来行时，availability标`history_scan_incomplete`，禁止把比较称当前有效。总行数、未来/坏行计数及截断诊断都不是模型输入，部分覆盖仍只描述实际扫描子集，不保证完整历史。有效未来失败行不打断已经收到的历史；无法可信解析时刻的坏行保守断链。

`calendar_at_as_of`沿用[日期模块](CALENDAR.md)：Asia/Shanghai星期、月份、日历季节、普通工作日/周末、2026节假日与调休，公告可用边界保持；未知年份保持unknown。这里的日期属于分析时刻，不是所有窗口内样本或门店营业状态的替代，也不建立全年统计规律。本版没有把日历或变化指标接到等待时间模型。

输出不含原始数组、数量快照、私有路径或传输头，只有汇总统计和已明确时刻/门店；`eta_available=false`、`true_no_show_rate=null`、真实训练标签0、通知false。本版为真实结果和日期回测准备可观察指标。后续需取得独立叫号/过号结果、可信首次接收与源延迟证据，再校准真实跳号风险和两种用餐预测。

## 本版实际历史回放

初rc32安装包只读E0237已完成的三份中关村匿名记录，在各成对响应结束的三个时点重建。队列/数量的可比对数均依次为0、0、1；原两进程边界各断开一次，没有把中断前后拼成连续变化。日期为2026国庆假期/10月，原数据库字节不变、客户端0/网络0/凭证0，ETAfalse/过号率null/首次持久接收unknown。这是同一小样本的三个回放时点，没有新采集或训练精度验收；独立私有报告/证明保留，详情见E0242。
