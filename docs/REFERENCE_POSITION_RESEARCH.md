# 第一位参考曲线的实验基准

2026-10-09继续核心模型研究，最初为下一步设计；本轮rc60已实现浏览器实验基准、同一数学模块的时间顺序回放与合成页面检查，云端现有页面仍rc57、此实验尚未部署。用户约定列表第一位作为当前叫号参考；rc58已把堂食绑定mixedQueue、预约绑定reservationQueue。此设计利用已采曲线准备可计算的实验输出，并与真实叫号等待模型分别验证。

## 可研究的目标

给定同店、同队列、同营业日的本人号码，研究“首位数字参考达到目标位置”的时间。仅使用第一位、原始顺序和实际接收时间；不取列表最大值，不把号码差标成已签到桌数。这个目标不是已验证的本人实际叫号或入座时间，误差需要正常用餐经历校准。

只有兼容的纯数字格式、已知当天取号与连续近期观测可进入计算。前缀／后缀、跨日重置、来源陈旧、失败、缺口或参考倒退要明确处理；不能拼成一条稳定速度曲线。数据不足或斜率非正时输出不可估计，不能补成零等待。

## 准备先比较的基线

在有界的近期窗口中，先比较普通末点差分与Theil–Sen配对斜率中位数；例如10／20／30分钟窗口。稳健斜率降低单个异常点的影响，但可能滞后于突发加速，因此同时保留最近一次原始推进及短窗口变化作为独立异常信号。参数只是研究候选，须用前瞻回放选择，不能直接称最优。

SciPy官方说明Theil–Sen使用点对斜率的中位数，并区分斜率区间与截距；[官方方法说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.theilslopes.html)。另可比较重复中位数，[Siegel方法说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.siegelslopes.html)。本项目后续可自行实现有界算术，不复制第三方源码或必须新增大型依赖。

不能把斜率置信区间直接包装成用户等待的90%预测区间。按时间变化的参考位置、窗口自相关、跳号和模型滞后都会影响未来位置；先显示不同窗口／情景下的实验范围，明确未校准，再以独立结果验证覆盖与误差。

## 与现有核心怎样相接

已有私有历史分布提供同店／队列／人数／桌型／日期的初估；参考曲线可形成实时快／稳／慢情景候选。本人号码和差值在私有计算内使用，AI仅接收已允许的公共趋势摘要与候选标识。DeepSeek权重受限、过期回退和预算机制保持，未配置密钥／预算时供应商关闭。

每天的参考曲线可以形成展示目标回放；本人实际叫号经历通过rc59草稿、首次接收和人工审核进入另一条等待误差验证。不能用展示到达的结果自动生成called事件。月份／季节／日型趋势需要跨日积累，首日数据不具备这些比较的支持。

## 核对顺序

1. 为连续片段建立精确时间输入，测试停止、倒退、重复、前缀、重置及缺口；只读资料，不新增官方GET。
2. 在每个预测时点只用已接收历史，比较多个未来提前量；使用[滚动预测原点方法](https://otexts.com/fpp3/tscv.html)，禁止用全天拟合后的残差冒充当时预测误差。
3. 再接手动号实验页面，区别展示参考估计与已校准真实等待；使用实际经历对齐和同期有／无AI比较。
4. 继续实现原两种预测、理想时间偏移语义、共享60／30秒、防过号提醒、长期每日服务与正式v1验收。这项基准不缩减既有要求，也不直接完成v1。


## rc60实现与限制

`src/sushiwait/web/reference-model.js` 是浏览器与Node共用的原创纯算术模块，无网络、存储或供应商调用。`forecast(detail, options)` 只接受指定门店、堂食或预约、今天和用户确认的当天取号时间，字段分别绑定mixedQueue与reservationQueue；最多2048日投影、64近期点。标准库时间戳检验保留实际接收时刻，只有最近90秒且不少于6点／5分钟的连续有效数据进入10／20／30分钟窗口；最大相邻间隔120秒。失败、暂停、缺号、重复／逆序／重启边界中断拟合，参考倒退后旧票据轮次拒绝；未来时间与本机时钟异常拒绝。全部原始数据仍由既有采集保存。

每窗比较点对斜率中位数与首末差分；至少一个正稳健斜率才计算。各正稳健窗口的到达耗时中位数作参考，所有候选的最快／最慢形成情景范围。最新间隔推进超过20位置／分钟且超过典型速度3倍，额外加入最新跳变情景；孤立跳变而其他斜率全零不外推。这些阈值为未校准实验参数，不是寿司郎业务规则；120分钟上限、停滞提示和样本年龄分别保留，位置差不叫前方桌数。零宽情景也不意味着零误差，当前没有校准的置信水平。

统计页表单在浏览器内计算，今天取号时间到分钟属于本人声明，不能证明轮次或实际取号。个人号码、时刻与确认不进入URL、请求体、访问日志、localStorage或服务端状态；关闭／重新加载页面后不保存。切门店、日期或队列后重新确认；30秒读取既有统计投影、15秒本地年龄重验，不增加官方查询。旧异步响应与旧失败不覆盖新选择；当前读取失败撤回旧预测。历史日期只看曲线，汇总／桌型队列不计算实验。源码静态资源、内网hub与公开网关仅增加同源脚本，公共API的eta_available仍false；没有公开私人追踪、结果提交或管理入口。

`replay(detail, {storeId, queueType, offset, stride})` 每个原点用当时及以前的前缀拟合，目标是假设当前参考再推进固定位置差，不是真人取号。未来观测仅核对首次达到目标的两次采样区间，保留不可计算、右删失和边界删失；误差到该区间及情景相交单列，不标成本人真实叫号、过号或实际等待的覆盖。禁止全年拟合后倒用未来信息。Node专项涵盖稳定推进、末点突变、零斜率、跨失败倒退、密度上限、完整/截断未来及浏览器队列确认／隐私／异步失败。

2026-10-09已保存的三店各136点被只读回放：堂食／预约各20、50、100位置差，每10点一个原点，共252假设案例；两家堂食26个可观测参考到达，另有不可计算及删失，成都这段均未形成有效数字原点。已观察的到达区间误差最大约58.5分钟，不能把此基准宣传为稳定实际用餐预测。其余参数与跨日历史尚未比较，不据此称最优；输入文件未修改，官方GET／真人结果／付费调用新增均0。模型需继续前瞻收集真实经历、同日期历史及有/无AI对比；主线两种预测、防过号通知、永久每日服务和正式v1仍未完成。
