## 保活与有效期

原固定Compose的`-keepalive-interval 0`关闭主动保活。新增[5分钟检查候选](../deploy/yyb_cloud_trial_keepalive.compose.yaml)仅修改这一个参数；固定镜像、UID、资源限制、私有会话目录、回环端口、日志关闭与有限停止不变。[内容守卫](../deploy/official_cloud_image.py)只接受逐字固定的原／保活配置与同一镜像完整层；任意更快间隔、公开端口或其它差异仍拒绝。

[固定供应程序的保活源码](https://github.com/525815266/YYB-Go-Enhanced/blob/2cc8f1697d1753061c491f394cc4ebb50811725a/internal/httpapi/keepalive.go)在正间隔时检查接近到期的账号；直连的默认提前窗口45分钟。未接近到期时跳过，不是每5分钟查询寿司郎。暂时失败按5分钟退避，确定过期则停止；微信撤销或要求本人验证时，仍需正常扫码。不能通过改数字延长微信授予的真实有效期，也不能承诺自动保活永远成功。

本人本次使用**现有账号的更新入口**，没有新增账号。更新链接有效30分钟、绑定原账号、成功一次即失效；二维码自身可能先过期。这个入口期限与微信会话期限、寿司郎JWT期限是不同概念，不能混作长期有效凭证。

## 失败后的恢复规则

1. 停止来源并保留旧终态、失败原因、未知结果与已花次数。确认真实service和最新响应时间，不重复同条件请求。
2. 在正常回环控制台查看现有账号状态；若要求重扫，由本人从现有账号更新入口完成。不得更换身份、读取聊天／其他账号或回退旧匿名通道。
3. 使用[控制器](../deploy/official_cloud_controller.py)明确的关联恢复阶段。旧账本不改；新账本继承全部尝试、revision、上下文摘要及已完成营业窗，manifest绑定前驱不可覆盖检查点。诊断失败仍占次数，后续正常重扫阶段继承15次并申请新的第16次，不复用未知的一次性code。
4. 同一阶段已经存在或失败时不可重建／清零。未经新凭证单店验证、完整同组保存和持久确认，不能写入选择标记或启动来源。生产启动只读取已验证的固定阶段；不自动创建恢复阶段。
5. 原collection任务继续恢复，普通213已用量保留，不补赶暂停期间的缺失点。来源／供应原停止定时器、同步尾窗保持。

当前补丁的离线验证覆盖错误分层、私有目录、继承计数、重复恢复、祖先篡改和未验证禁止切换；合成验证不证明微信会话已经自动续期。真正长期保活需要自然到期前后供应与新查询证据，不能用提前请求、文件期限或页面在线替代。
