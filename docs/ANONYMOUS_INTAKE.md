# 匿名观测的本机首次接收

开发候选0.2.0rc33为新写入的匿名观测增加本机首次接收元数据，补充[响应窗口分析](ANONYMOUS_SIGNALS.md)。例如一份12:00返回的记录，12:10才交给采集库：按首次接收回放时，12:05不会把它当成已经收到的数据。它为后续预测的时间边界提供记录，不认证真实叫号结果、上游新鲜度或模型精度。

## 新采集与历史回放

现有`remote-snapshot`、`remote-collect`、`remote-monitor`及持久窗口/服务均通过同一个`RemoteStore.append`保存。本版在写事务内读取本机UTC时钟，保存`local_intake`的版本、接收时刻和绑定规范观测/run/时刻的SHA256。调用者传入的同名字段不会被采用。两条已尝试查询必须已经结束；接收时间早于成对响应结束、早于上一份有接收元数据的记录，或上一条元数据损坏时，停止写入并回滚未提交事务。相同接收时刻允许出现多条独立采样，不把它们合成一个事件。

SQLite仍为匿名schema1，原列和查询返回格式保持。旧行不会被修改或补出首次接收时间；旧程序正在运行时不会获得这个能力。升级使用新包须另行启动新的采集或在任务结束后按原规则恢复，不能为了升级重开正在验收的原24小时窗口。新元数据只保存在私有库，号码服务和`remote-report`的公开字段记录不返回它。

使用新数据时，可以明确选择：

```sh
sushiwait remote-signal-report --db /absolute/private/remote.sqlite3 \
  --store-id 3014 --as-of 2026-10-06T14:00:00Z \
  --availability-basis local-first-receipt --window 120 --max-gap 90
```

示例是格式，不是已部署库。工具只读操作者明确指定的已结束库；父目录锁、权限、响应与完整记录校验仍保持。默认`response-completion`保留rc32描述性响应时间重建；选择`local-first-receipt`时额外要求有效接收元数据不晚于as-of。旧行缺失元数据不进入这一筛选，也不能跨过这些未知行连接比较；损坏元数据不能被当作旧行。接收之后的失败记录不会倒灌到此前的窗口。有界最新ID扫描若被未来响应或未来接收占满，标历史不完整。

首次接收用于判断当时收到哪些记录；实际变化和覆盖仍按两端点各自的响应时钟计算，不能把集中补录的接收间隔当叫号速度。它没有把当前24小时库搬进新库，没有增加后台查询、改预算、联网回放或生成ETA。

## 时间证据的限制

接收时钟在事务内、提交前读取。这是本地程序接受完整记录的时间，不证明另一个进程当时已经可读取或持久落盘。拥有本机/数据库的人可以改变时钟或重算校验值；SHA只能检查未同步修改的损坏，不是外部认证或不可篡改审计。第一次从旧库重新导入的时刻只能算本次接收，不能冒充历史首次接收。

输出保留`historical_availability_verified=false`、`durable_availability_verified=false`、`independent_time_attestation=false`、`verified_training_labels=0`、`eta_available=false`和真实过号率null。接收格式与时间筛选不等于可训练资料已经齐备；仍需源身份/单位/刷新验证、实际叫号结果及审核、预测日志和时间回测。完整实现、软件/安装/真实结果及公开状态以[交接记录](PROJECT_HANDOVER.md)为准。

## 本版实际验证

本机20项专项与完整920项检查通过；最终38模块安装及checkout外CLI检查通过，合成接收前/当时筛选为[0,1]。正常关闭官方小程序后，已安装本版对三试点各查询一对，总六次GET全200；每份本机接收时间不早于成对响应结束，只读截止回放均在接收前排除、当时纳入，原库不变、回放网络0。它验证本版真实记录与时间筛选链路，不认证源更新时间、单位、历史持久可用、真实过号率或模型表现。原rc31的24小时任务另行持续，未被此试验替换。
