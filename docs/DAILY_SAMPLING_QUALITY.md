# 每日采集质量报告

rc65 在闭店归档时增加私有 `quality.json`，与 `projection.json`、`result.json` 同目录保存。报告关注数据是否收到、哪里出现断档，不新增门店请求，也不修改既有原始库或归档。今晚待交接的服务器版本仍固定为rc64；新报告尚未部署。

也可以对一份明确指定的已保存原始日投影离线运行：

```sh
sushiwait daily-quality-report --projection-file /private/path/projection.json \
  --store-id 900001 --date 2026-10-09 --as-of 2026-10-09T22:05:00+08:00
```

示例店号是合成号码，不用于真实查询。输入文件必须0600、父目录0700，最大2MiB；命令只读取该文件，不打开数据库、不建立采集器。HTTP旧副本附加了lineage字段，应使用原保存投影而不是附加后的网页响应。

报告分别统计查询操作开始和队列响应接收所在的背景采样格。操作开始时间包含本地准入等待，不等于网络实际发送时间；响应接收时间也不等于餐厅叫号时间。参数默认背景60秒、断档阈值90秒，两次响应接收偏移另列。数量查询失败时，已成功收到的队列仍用于接收覆盖，整组失败单独保留。

统计截止以投影的 `generated_at` 为准。较晚运行报告只增加投影年龄，不凭空把之后时间算成断档；当前尚未结束的采样格排除，闭店最后不足一个完整周期的格才结算。午休等非营业间隔不算接收断档。图形被截断时，只报告返回部分的下界，全天缺失数和完整覆盖率保留未知。

输出包括完成格覆盖、最长缺失串、开店至首响应和末响应至截止的缺口、内部接收间隔、失败原因与时间异常。堂食／预约第一位的倒退或快速推进仅作展示变化计数，不转换为实际叫号量、过号率、等待桌数或人流。

`declared_day_observed` 仅表示当前完整投影在用户假定营业表下未检测到上述缺口；不证明官方营业时间、来源新鲜度、门店身份、实际叫号、独立备份或预测精度。报告警示不会自行重放缺失查询。新日控制器按确定截止和规范JSON不可覆盖保存，归档中断后复用完全相同的报告；旧归档没有此文件仍可读取，不补造历史。

本功能用于每天自动给出一次明确诊断。已通过且没有变更的检查不反复执行，真实闭店交接与次日启动按已安排时间观察，预测开发同时推进。
