# 已有号码的自动更新后台

rc50把[私人已有号追踪](MANUAL_TICKET_TRACKING.md)连接到持续读取写者投影、异步计算、当前版本提交和门店共享采集需求。输入仍是用户已经拥有的号码，没有自动取号、取消、签到、重排或登录。这里是后台库和有界CLI，尚无用户输入页面、通知送达或已校准ETA；真实结果认证标签为0。

## 两种刷新各做什么

追踪读取者默认每5秒从**本机采集服务**读取一次投影，同一店多位用户共用这一读取，最多16份私人会话／3店。它不查询寿司郎接口，不打开写者的SQLite，不使用微信凭证。同一条源响应的再次读取不会被称作新采集；没有内容变化时，最多每30秒建立一个私人时钟更新，用于条件剩余计算与失效状态更新，不认证叫号事件或源内容新鲜度。

门店采集工作者仍按照原任务的共享策略执行。理想到店前30分钟／15分钟分别请求60／30秒，较早研究叫号端只能提前；本人号码曾进入当前展示后，状态未知也请求30秒。多人同店只形成一个最紧迫目标，每次采集仍是一组两条独立GET。读取者本身不会越过采集预算、期限或失败规则。

`+10/-10`保留原用餐偏移语义。未知理想到店时间保存为null，不为取得30秒策略编造到店或已叫时间。列表出现／消失、号码差、快速周转都不认证精确前方桌数、已叫、过号或真正爽约率。

## 投影与模型并行

新只读路由为`GET /api/v1/stores/<store_id>/tracking-projection`。写者在同一进程投影锁中复制号码和历史，避免本地两次读取跨提交；`local_projection_atomic=true`只说明这个复制，`upstream_snapshot_atomic=false`保持。两条上游请求、工作者生命周期与响应身份没有因此获得原子性或认证。

CLI只接受显式`http://127.0.0.1:<port>`，路径固定，没有环境代理、重定向、身份头、Cookie或任意外部地址；每次读取最多2MiB、socket超时5秒。超时是socket规则，不能宣称完整操作的硬墙钟限时。投影格式、店铺、时刻和本地响应状态均须通过校验；无效或不可读即停止，不盲重试或用旧成功继续发布。

计算最多四个线程，每份会话最多一个待完成计算。读取和观测提交不会等待模型，新的私人版本可以继续前进；旧计算、旧先验回退、用户结束和到期均要通过[原子提交检查](MANUAL_TICKET_TRACKING.md)，失效整条结果拒绝，不覆盖新观测。运行关闭后待完成计算不能再提交；关闭追踪不取消官方号，不伪造用户终态。

历史入口只读明确闲置的结果／审核库，按观察当时已接收与已审核的记录计算完整条件区间。库函数另可接受调用方的完整候选构建器；目前没有拟合真实快／慢／正常情景。条件时钟更新本身可以改变剩余时间，固定历史条件下叫号时刻包络可能保持相同，这不能冒充已学习实时趋势。

可显式连接[DeepSeek适配器](DEEPSEEK_ADAPTER.md)：只有多情景且数值融合比例大于零才可能请求供应商；必须同时给私人钥匙、持续预算和`--allow-paid-request`。默认关闭，不读模型钥匙、不计费。传出的只有白名单公共特征、日期和候选名称，个人号码、取号时间、分布、用餐计划及标识留在本地。公共建议可实际重算私人分位点；同一真实观测的时钟重读不重复发起POST。

迟到请求仍保留独立预算账本的消耗；未知结果不退款、无自动重试。同一目录锁检查当前版本，尚非分布式多用户系统或通知原子性。当前CLI历史入口仅生成历史情景，所以不会为了“用上AI”制造多情景或无意义付费；真实训练与同期有／无AI回测仍需完成。模拟传输不是供应商输出或计费验收。

## 共享需求有期限

新私有计划可包含`polling_request: {interval_seconds, expires_at}`及`plan_expires_at`。请求仅接受30、60或配置背景间隔，租期最多300秒；自动追踪写60秒需求，在剩余30秒时续写。个人会话结束、到期或观测上限到达后不再请求高频；追踪进程退出后，未知到店时间的旧加速需求到期退回背景。已知用餐计划的正常60／30秒时间带仍独立有效，整个计划到期后停止该个人需求；门店背景采集继续由工作者负责。

输出是一份**专用完整计划集合**，必须显式指定UUIDv4的`plan_series_id`及独立0700／0600路径，不能拿其他操作员的文件覆盖或自动合并。私人会话锁持有到计划原子提交结束，新版本或本人终态不能与旧需求发布交错；工作者另行核对和接受修订，不因文件已写而声称采集已提速。生成器不保存号码或episode标识到计划集合，不输出私人时间。

## 显式启动新任务的步骤

当前运行中的rc43／rc45真实六店任务保持原版本、周期、期限和预算，**不重启、不升级、不扩展**；它们没有这个新路由。下面仅用于之后明确启动的rc50+任务或合成验证，不对当前活库执行。

先用`ticket-track-init`为已有票据建立空私人会话，真实用户用`self_reported`、未知字段用null／unknown，详细格式见[输入说明](MANUAL_TICKET_TRACKING.md)。准备彼此独立的私人会话、工作者状态、不可变初始计划和共享修订目录；初始计划可为`{"schema_version":1,"plans":[]}`。然后用自己生成的新UUID替换下例的合成series，真实门店号需已核对，不使用合成900001访问上游。

```sh
sushiwait ticket-track-run --state-dir personal/state --store-id 900001 \
  --prepare-plans-only --plan-output demands/plans.json \
  --plan-series-id 00000000-0000-4000-8000-000000000001
```

这一步只生成私人需求，不读门店或调用模型。之后在一个独立进程启动同店范围的有界工作者，将`--plan-updates-file demands/plans.json`接入`remote-window-serve`／`remote-campaign-serve`；具体期限、预算、状态与实际门店由操作者按[采集窗口](ANONYMOUS_WINDOWS.md)／[多日方案](MULTI_DAY_COLLECTION.md)配置。不能复用已终态任务来重置限额。

```sh
sushiwait ticket-track-run --state-dir personal/state --store-id 900001 \
  --collector-url http://127.0.0.1:8765 --duration 3600 --max-cycles 720 \
  --plan-output demands/plans.json \
  --plan-series-id 00000000-0000-4000-8000-000000000001
```

需要数值历史时另给`--source-db`与`--reviews-db`，两库及模型预算／钥匙不能位于会话或共享计划目录内。省略历史仍可观察本人号码、保存资料不足并更新采集需求，不制造零等待。重复`--state-dir`可加入同店其他会话，共用一份读取和门店目标。

单次最长6小时、最多4320读取周期，本机读取间隔5–30秒；每个周期最多3次本机GET。私人会话原截止最多24小时、最多2000观测不重置，频繁真实变化可能更早耗尽上限；需要明确检查或建立下一真实计划。单次周期／时长上限不等于永久守护进程或跨重启读取计数预算。旧模型请求的持久付费预算另行保持。休眠／离线不追赶读取或采集，长期部署与提醒仍待验。

标准输出只含周期、读取、提交、拒绝、请求等聚合计数，不含号码、会话路径、个人行程或模型钥匙。模型和私人结果仅留在0600文件；取号时刻缺失、历史不足、资料停止／失效等继续明确缺失。所有数值仍为研究区间、`eta_available=false`。

## 已验证与下一步

检查覆盖真实线程的新观测优先、迟到模拟供应商结果拒绝／保留预算、公共权重改变数值、同店去重、时钟更新不重复POST、未知状态与断采、需求租期、真实共享调度程序及截止／预算、私有文件和实际CLI；内容与传输为合成，不是模型误差或真人用餐结果验收。安装、Linux、真实本机HTTP链路和精确公开CI证据随[交接记录](PROJECT_HANDOVER.md)分别记录。

继续完成真实快慢模型、自然用餐结果及时间顺序回测、实际供应商与费用／延迟、通知送达、产品前端和正式服务器运行。原两种预测、理想时间反向建议、不同日期／月份／季节、跳号波动以及后置自动业务要求均保留；没有正式v0.2／v1发布。

## 相似日期参考

rc51可重复给`--trend-profile-file`接入每店一份已封存参考，按其窗口长度整理当前投影并注入公共数值特征。匹配日型／周几／时段／月份／季节，比较有效覆盖与采样间隔；资料不足的四个参考字段全部null。参考启动时读一次、需独立私有目录，当前rc43／rc45活采集不升级或外读。完整生成、前瞻重建依据和研究边界见[趋势参考](TREND_PROFILES.md)。它不直接生成等待分钟，单一历史候选仍不调用付费模型。

rc52可配置每店一份`--trend-archive-file`，启动时载入完整不可变档案快照，每轮按当前日期及可比间隔动态选取；相同条件的同店用户共用一次参考选择，私人预测仍独立。选取后再次整理同一复制投影以保持创建／观测时序，不额外GET，不打开活库。与同店静态参考不能同时配置；完整范围、上限及冷启动见[长期档案](TREND_ARCHIVE.md)。

rc53增加显式--sealed-remote-db及landmark／窗口／邻居配置，需独立source-db、reviews-db和闲置封存匿名库。真实线程拟合[实时邻域候选](REALTIME_NEIGHBORS.md)，走同一私人新版本优先和公共AI流程，原付费授权默认关闭。无当前资料或独立标签不足回退历史，活库拒绝读取；没有升级正在运行的rc43／rc45任务。
