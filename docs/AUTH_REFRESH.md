## 可执行的状态检查

dev4新增以下零网络检查，不需要把私有上下文放进环境变量：

```sh
PYTHONPATH=src python3 -m sushiwait auth-status --api-profile miniapp_gateway --credentials-file "$SUSHIWAIT_CONTEXT_FILE"
```

整组文件沿用当前安全读入、profile/schema/权限限制，不与环境拼接。输出只含安全声明时间、revision、checked_at和本机保护状态，不含文件路径、请求头、账号字段或凭证值。文件验证后才读取当前时间，不修改文件或数据库。

| authorization_guard.state | 含义 | 后续采集的处理 |
| --- | --- | --- |
| no_declared_stop | 声明可解释且当前没有触发30秒保护 | 仍需正常只读请求验证当前接受；这不是服务端有效性结论 |
| stop | 声明过期、临近到期或时间顺序无效；stop_reason区分原因 | 不发查询；取得完整正常新上下文后重新检查 |
| unknown | 声明不可解释或缺到期时间 | 不推默认TTL，不等于已到期或无限有效；当前查询逻辑仍按既有规则处理未知声明 |

exit0 / ok=true表示检查完成，**stop或unknown也会exit0**。文件缺失、损坏、权限不安全或profile不符为固定安全错误/exit1，不回退环境。每次命令是独立检查，不保存跨进程revision历史，也不证明更新后的服务端接受。省略文件参数时原环境模式及原输出保持。

该功能没有实现定时器、告警送达或自动更新；后续后台必须读取保护状态，不能仅凭退出码决定是否发查询。


## 已实现的辅助路线

dev5的同电脑辅助路线为：正常客户端成功单店GET→Surge被动响应适配器→最多60秒的127.0.0.1接收器→完整新上下文原子revision提交。collect可以显式等待最多600秒，收到更高revision、不同授权且通过本机保护后恢复。它不生成登录码、不签初始化、不主动驱动官方刷新；没有实际电脑微信/Surge回环联动或无人值守验收；本轮真实到期暂停/600秒超时已发生，因无新上下文仍没有真实恢复。合成回环与模拟上游检查已通过，操作见[BRIDGE.md](BRIDGE.md)。

接收器结束只关闭本机端口/清理自己的session文件；不能替操作者关闭Surge解密与捕获。适配器过期后不再转发，但不等于MitM关闭。本轮未安装实际配置或新开调试。

## 下一步的实际进入条件

1. 在已有正常账号的可观察运行环境中，验收正常新查询上下文进入本机接收器，不需要反复导出HAR；保持仅sapi、短窗和凭证本机范围。
2. 实际revision3+提交后用固定GET核验服务端接受，再在同一采集进程跨到期、更新、恢复，验证无混头/过期请求/追赶流量。文件提交成功不替代服务端接受。
3. 落实可长期运行的正常登录码/上下文提供方或正式第三方接入。当前静态签名证据与短时辅助端不足以构成全天服务器方案；设备和头来源仍要完整核对。
4. 只有得到可用方式、应用身份和真实错误分类，才实现受支持的自动提供方；不加入假续期、旧登录码重放、官方常量或凭空默认TTL。
5. 继续字段现场对照、源刷新/限流/长期可靠性和真实事件标签。用户离开电脑后自主推进可执行部分，密码/设备认证仍需本人；不绕过认证、不要求日常人工刷新采集。
