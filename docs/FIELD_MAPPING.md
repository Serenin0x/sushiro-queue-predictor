- request_started_at：电脑开始这次请求。
- received_at：电脑收到并处理这次响应；失败记录依据 failure_phase 解读。
- HTTP Date：服务端/网关生成响应的时间提示，不是队列更新时间。
- source_updated_at：已核实的门店源更新时间；当前为 null，upstream_freshness=unknown。

页面刷新后时间变化不证明号码数据变化；客户端在错误时也更新时间，后续展示须分别表达最后尝试、最后成功及源新鲜度。内容相同既可能是没有变化，也可能是缓存；内容变化只证明两次公共字段不同。

## 缓存和限流响应提示

2026-10-04 17:15:21正常详情响应：HTTP Date为17:15:22、X-Gateway-Cache=MISS、CloudFront提示Miss，Cache-Control含max-age=0、must-revalidate、no-cache、no-store、private。X-RateLimit-Limit=60、Remaining=59。

这些是一次响应的声明，不能解释成“每分钟一定允许60次”、官方允许全国采集、源数据没有缓存，或相同配额适用于所有用户/端点。没有为寻找限流上限进行压测。当前只在1–3店、30–3600秒有界范围内采样；HTTP429首错停止，没有自动重试。

工具可保存固定白名单的类型化 transport 提示：HTTP Date、Age整数、max-age整数、三项缓存布尔值、HIT/MISS/BYPASS枚举、限流上限/剩余整数、数字Retry-After。异常值保持未知；不会保存任意响应头、Cookie、设备风险值或网关标识。数字Retry-After只供检查，不触发自动等待重试。transport不参与门店内容哈希与号码变化比较，旧记录没有该项仍可读取。

## 预测仍需要的证据

有限三位展示号的推进不能直接算真实过号率或以号码差乘固定分钟。后续预测需持续历史、日期/时段差异和真实叫号/入座标签；本人已有号单的状态采集还要独立业务授权。当前 v0.2.0 交付接入验证能力，不提供等待时间预测或精确误差。
