# 统计页更新与历史记录

2026-10-12 E0469，源码v0.2.0rc83。原统计地址继续使用；公开显示以已部署rc79为基础更新五份统计资源，官方查询库仍为冻结rc82，不能混作整套服务升级。

## 使用

主统计页页头的“早期记录”打开同样的日历，可查看旧采集的10月9日7,920组、10月10日28,604组，按城市、门店和日期进入表格与曲线。页头“返回当前采集”回到新官方数据。主页面已有10月10日官方六条及之后记录也保留。两类观测保持原来源和原始时间，不拼接成一条速度曲线；旧采集的拒绝保护与缺口仍保留。

网页按后台采样策略更新，目前10分钟一次。它读取服务器已保存的副本，不因有人查看而查询寿司郎。首次打开与主动换范围可显示加载；同范围自动或手动刷新保留号码、表格、曲线、选择、焦点和页面位置，只有变化的数据被替换。刷新失败仍明确提示并撤下旧结果。保留画面不会给旧号码续新鲜度，页面读取时间和原响应时间分别显示。

## 接线

- `/statistics` 明确绑定 `sapi_miniapp_gateway`；`/statistics-history` 明确绑定 `crm_remote_v1_1`，两者共用日历资源。
- 原官方和旧统计API保持各自固定路径。历史入口不是官方接口失败后的回退；仅用户明确选择该入口时读取旧存档。
- 只读 `/api/v1/statistics/settings` 返回 `{"schema_version":1,"poll_seconds":600}`；不包含私有文件路径、预算、凭证或管理接口。网关 `--refresh-policy-file` 读取采集器同一政策文件，页面首次绑定及后续已保存数据读取完成时同步周期。
- 控制器以 `refreshing` 表示同范围后台读取，保持原phase和数据；完成或失败仍按既有取消、范围与来源校验。动态周期只接受30–3600秒，不重叠读取。
- 图表／表格继续差异更新，未变化的点版本不重画；提示区预留稳定空间。按钮不会在后台刷新时旋转、号码不会先变为“更新中”，图表也不会模糊。
- 设计资源摘要见 [statistics-refresh-resources.json](design/integration/statistics-refresh-resources.json)，供后续设计任务保留这些内容与行为。
