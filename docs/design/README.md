## 产品与用户任务

展示名为 **SUSHIWAIT**，仓库名保持 `sushiro-queue-predictor`。服务面向中国大陆寿司郎门店，帮助用户看到叫号变化、估计自己的等待、安排到店时间，并在突然加速时及时调整。项目为独立开源软件，产品文案不表示寿司郎官方运营或授权。

用户的主要任务按此顺序组织内容：

1. 找到想去的门店，查看最新堂食／预约展示号和数据更新时间。
2. 已在官方客户端取号的用户输入自己的号码，查看随新观测更新的预测及误差状态。
3. 尚未取号的用户按理想用餐时间和等待偏好，查看建议取号时机；这是后续两种预测中的反向模式。
4. 查看月历和单店当天曲线，了解不同时段的号码变化。
5. 临近用餐查看提前叫号风险，并记录正常用餐的实际时间，帮助校准模型。

自动取号、取消和重排保留为后续阶段。精确逐号发放时刻只做研究，不在 v1.0 部署。设计这些后续内容时应明确阶段，当前界面不显示看似可用的执行按钮。

## 设计任务的交付内容

每一页面应交付：信息顺序、字段及说明、输入与操作流程、加载／空数据／失败／闭店／过期／资料不足状态，以及手机和桌面上怎样完整表达内容。当前先交这些内容，视觉方案另行处理。

对新增功能写明：已有接口还是待接入、依赖哪个模型结果、哪些操作仅在本地发生、哪些以后需要私人服务。设计稿中的数值样例标明合成，不作为真实统计或上线能力证明。

每次实质设计变更同步本板块和[完整交接历史](../PROJECT_HANDOVER.md)，记录改了什么、原因、对应要求、实现阶段及下一步。不擅改正式Logo、README已认可视觉或采集／预测业务语义；正常内容调整在已授权范围内继续，不为日常编辑重复索要确认。

## 2026-10-14 提交式号码流程

2026-10-16 E0527更新：预测与记录采用两个独立草稿页签，每条表单各自选择城市、门店和队列；预测有号码、今天取号时间、签到与模型模式、录入／持续跟踪复选项及提交。历史记录有独立日期／时间，无复选项。提交成功短暂勾选动效，随后我的号码卡片；记录卡仅记录，预测卡显示剩余分钟、时刻范围、更新、手动刷新和跟踪开关。保持不可变提交输入、重复幂等、失败重试、隐藏停租和轻量无布局位移更新，支持键盘页签与减少动画偏好。

公共API保持原合约，`/model-advice.json`只含公共建议，`/wait-reference.json`只含满足样本门槛的匿名汇总。私有`POST /api/v1/research/tickets`使用schema1／action submit或list／owner_secret正文，GET不提供个人号单；预测不足也存，HTTPS Origin和scheme必须匹配。公开`POST /api/v1/prediction/presence`只含client_id／store_id／queue_type／mode／visible，不含个人号码／取号时间或能力凭据。完整字段与实际可用状态以[当前接线](../EXISTING_TICKET_LIVE.md)及[交接](../PROJECT_HANDOVER.md)为准，HTTPS已启用，原HTTP地址同路径跳转；不得把HTTP伪造Origin当成加密。

## 2026-10-16 截图填表与批量提交

预测／录入页签共用平面填写区，截图工具仅保留上传按钮与拖入状态，不再嵌套圆角卡片。每张图片填入一条普通可编辑表单；号码、城市→门店、日期、分钟级时间、签到及队列都可修正。上传后不自动保存、不自动预测，不展示另外一组OCR文字。识别开始后的人工修改不会被迟到响应覆盖。

图像接口只返回识别字段，持久提交仍复用原私人接口和幂等逻辑；不把图像、完整OCR文本或私人记录混入公开数据合同。具体边界、部署和验证见[截图录入](../SCREENSHOT_IMPORT.md)。
