# 主日历与工程面板整体重规划提案

2026-10-13，R68／E0504。**状态：2026-10-13本人已批准开始实施，生产新布局尚未部署。** 用户已明确范围为工程面板和主日历统计页；布局、图表、导航、点击、刷新、手机交互一起规划。图标沿此前Tabler官方方案，避免自创图标。当前优先修复凭证更新故障，之后继续本方案；线上原界面保持。本提案不代表新增接口、实际模型精度或服务器管理能力已经存在。

## 1. 重新组织的依据

现有工程页把共享筛选、四项指标、第二个月历、多段解释、三个纵向图表和明细放在较长的页面里。分类切换已经存在，但每个栏目内部缺少主次；曲线绘制目前缺少点选、悬浮详情和时间缩放。主日历默认展示全国历史目录，当前只有北京和成都的三家新采门店，今天其它城市成片显示“暂不可用”，容易被理解为所有门店请求失败。采集组数又容易与人流量混淆。

重新设计围绕四个连续动作：**看全局 → 选门店 → 看当天趋势 → 查具体采样记录**。每个页面只回答一个主要问题。预测实验与本人经历按独立流程组织，共享门店身份但不共享无关筛选、公共URL或私人表单数据。

研究参考：

- [Tabler 官方页面布局](https://docs.tabler.io/ui/layout/page-layouts)：采用免费开源布局中的纵向导航、页标题、工具区与卡片分工，延续既有图标和Logo许可；不复制示例里的假账号／通知。
- [Ant Design 布局规范](https://ant.design/docs/spec/layout/)：固定左侧导航，右侧随屏幕调整，统一间距和内容对齐。
- [Grafana 仪表板实践](https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/)：由总览向细节逐级进入，一个图表回答一个问题，不把单位与尺度不同的指标堆在一幅图里。

以上是借鉴依据；下面的结构和数据语义是SUSHIWAIT自身的设计提案，不是这些项目对寿司郎数据的结论。

## 2. 两个入口与共同框架

| 入口 | 主要使用者 | 首屏职责 |
| --- | --- | --- |
| `/statistics` 主日历统计页 | 日常查看数据的人 | 选城市／门店／日期，看已保存数据和趋势 |
| `/statistics-legacy` 工程面板 | 维护人员、开发者和预测研究者 | 看数据是否更新、定位缺口、检查样本和实验 |

共同保留原地址、来源合同与独立公共归档；历史数据按原日期纳入已有记录，既有来源间不拼成一条轨迹。默认浅色、红色强调，红色主要用于选中、主操作和异常；不把所有卡片标题涂红。深色开关已有能力保留，其排布跟随共同组件。

桌面工程页左栏约224px，可折叠成图标栏；顶栏约56px。Logo保持原矢量比例，不拉伸。顶栏只放面包屑、公共数据更新时间、手动读取、主日历／工程切换与真实文档入口。页面读取时间与上游响应时间分别标注。用户头像、假消息通知、采集开关和登录入口不为装饰而添加。

主日历使用更轻的顶部导航：月历、当天数据、工程入口。复用日期、门店选择和图表组件，避免维护两套字段语义。

## 3. 主日历：月、日、店三级

### 月历首屏

顺序为：品牌与工具 → 城市／门店选择 → 月份导航 → 月历 → 选中日期简要摘要。

- 当天默认显示有实际采集记录的范围，明确“当前采集3家”；其余已知目录另有“历史门店”入口。历史日期展示那天真实有记录的范围，不用今日三店覆盖昨日147店。
- 格子主要显示日期、日型、记录状态；采样组数作为小字。颜色先表达资料覆盖，不标“人流量”，也不用更多采样必然更忙的逻辑。
- 悬浮／键盘聚焦日期可看简要提示，点击选择日期，再点“查看当天”进入详细页；手机点击直接打开日期摘要，操作一致可返回。
- 月历摘要不塞入大曲线和全部门店明细。没有记录、未开始采集、来源失败、历史资料不可读、未来日期分别呈现。

### 当天数据

顶部日期栏含前一天／后一天／日期选择和返回月历。下方仅保留三项核心摘要：有记录的门店数、成功采样组数、最后收到时间；完整性说明另有详情。

门店列表每行显示：门店名、当天采样数、最后采样时间、资料状态、短趋势预览。默认先显示当前范围内有数据的门店；排序和搜索在列表工具栏内。点击门店进入门店详情，返回保持城市、日期、列表位置。没有新观测与成功响应但空数组不混成一种状态。

### 单店详情

首屏为门店名＋日期、堂食／预约切换、最新采样的原三个展示号及真实响应时间。陈旧记录仍可在“最后采样快照”中查看，实时判断单独明确失效；不让页面刷新时间替旧响应续时。

中部是一幅宽主图；底部是“采样记录／资料说明”标签页。公开详情读的是保存数据，不再查询上游；没有取号、取消、重排或服务器控制按钮。

## 4. 工程面板：按任务组织导航

只保持两层导航，展开父组只改变导航，点击子项才切内容；活动子项所在组始终展开。折叠图标栏提供名称提示和键盘操作。

| 左侧分组 | 子项 | 页面主要内容 |
| --- | --- | --- |
| 数据观测 | 采集总览 | 最新已保存观测、门店更新列表、明确失败／断档提示；不放第二个完整月历 |
| 数据观测 | 门店分析 | 门店＋日期＋队列，一幅主曲线、关联采样表、详情抽屉 |
| 数据观测 | 数据质量 | 按日或门店看真实失败、间隔、缺口与来源边界；查看对应采样 |
| 模型与记录 | 预测实验 | 输入、结果、调整原因分区；模型方法和限制可展开 |
| 模型与记录 | 用餐记录 | 新建／继续草稿、事件时间线、下载／导入；修订保留 |
| 左栏底部 | 文档与GitHub | 真实链接与版本信息，不占数据工作区首屏 |

“采集总览”表示归档中的更新情况，不凭最后样本就显示“服务器正常”。现有公开接口没有进程探针或管理权限；实时服务诊断只有以后独立的受限接口真正上线后才可以显示，不能从公开页执行管理操作。

页面筛选按任务裁剪：总览只需日期和地区；单店分析只需门店／日期／队列，月份不重复放；质量页的高级筛选收进面板；预测默认今天，历史回放单独显式进入；用餐草稿不跟随统计页切日期自动改内容。

## 5. 图表重规划

| 图表 | 默认位置 | 要回答的问题 | 表达与限制 |
| --- | --- | --- | --- |
| 展示号码随时间变化 | 单店主图 | 当天展示号如何移动？ | 原始采样点；第一位红色主序列，第二／三位默认淡色可关闭；点序列与同队列原顺序一致 |
| 参考推进速度 | 主图下方可选展开 | 近期参考位置是否加快？ | 仅可比连续观测之间计算，单位“参考号码／分钟”；不是实际带位桌数或真实过号率 |
| 采样质量时间条 | 工程分析／质量页 | 哪些时间有数据，哪些存在缺口？ | 成功、失败、边界与未知分别标识；按真实采样策略解释，不把十分钟基础格当平滑计划完成率 |
| 原始数量 | 工程高级项 | 接口原数量怎样变化？ | 单位已核验才显示对应名称；未知时注明原字段／单位未知，不称人数／桌数 |

主图横轴为响应时间，提示框同时显示请求开始和接收时间。堂食、预约使用独立视图，不把1–6999与7000–7999号码硬叠在同一轴。不同来源、失败、长缺口和重置边界断开；不平滑造出中间叫号时刻。默认点线展示，连接只用于合法同段的趋势示意，不表示连线上每个号码实际出现过。

图表工具仅保留常用项：全天／午间／晚间、时间范围缩放、恢复全天、图例开关。样本少时保留原始点，不用空图遮掩。日与日比较是后续可选功能，只在同门店／队列／来源可比时使用分面或独立曲线，不先堆入首版。

交互合同：

1. 鼠标悬浮显示时间十字线和该真实点的三个号码、原数量、状态、来源；没有该时刻观测时不造最近点的叫号时间。键盘和触摸可选择同样的点。
2. 点击点可固定选择，联动下方表格行；再点“查看记录”打开右侧详情抽屉，手机为全宽详情。表格点行反向定位真实图点。
3. 关闭抽屉保留缩放、选点、筛选和滚动。Esc关闭、焦点返回原入口；触摸不依赖悬浮。
4. 自动读取新样本时只追加必要数据；用户已缩放时保留范围并提示“有新采样”，点击才跳到最新。查看历史日期不自动跳今天。
5. 表格默认时间倒序，可排序／分页，保留原三个号码与状态；下载只导出当前可见范围对应的真实公共记录，单位和来源写入说明。需要新增导出接口时独立验收。

未来逐号表只能标“首次观测／未观测”，不能把采样时刻称精确叫号时刻，也不能将没出现的号码自动认定真实过号。真实过号率与人流量仍需额外业务证据。

## 6. 输入与点击流程

**预测实验**：左侧紧凑输入（门店、队列、本人号码、已知取号时间，可选到店偏好），右侧结果与更新依据；手机上下排列。首次输入后明确“参考实验”的性质，算法详情折叠。未知输入明确允许未知，错误靠近字段。私人号码、草稿内容不写入URL、公共归档或LLM。未配置真实AI时不显示“AI正在计算”。

**用餐记录**：先选择新建或继续草稿，再补门店／号单，再在时间线增加取号、签到、叫号、入座等事件。精确／大约／未知选择贴近时间字段，不一次展开放大整套表单。保存、下载、导入的结果明确；修订保留原历史，清空仍需要具体确认，切栏目和自动更新不销毁草稿。

**筛选与路由**：门店、日期和队列是页面上下文，写入不含私人内容的URL状态，支持复制链接、浏览器返回和重新打开。快速切换采用最新选择胜出，旧请求不能覆盖新选择。多字段高级筛选一次应用，单个常用切换即时响应。新增确认只用于清空／覆盖等实际有影响的操作，不为查看记录增加确认框。

**刷新与状态**：第一次加载只在对应区域显示占位；后台读取不插顶栏“正在读取”、不清空整页、不移字体。读取失败保留可识别的历史数据，标旧时间；可执行实时判断暂停。空数组明确“该次响应没有展示号码”，缺字段明确“未显示”，HTTP错误单列。预留状态区防止布局跳动。

## 7. 草图结构与手机适配

单店分析桌面结构：

```text
左侧导航 │ 面包屑                         工具区
         │ 门店名称 / 日期                 资料状态
         │ [门店] [日期] [堂食/预约]       [更多筛选]
         │ 最近采样前三位                  原响应时间
         │ ┌───────────────────────────────────┐
         │ │ 主曲线：时间 → 展示号码            │
         │ │ 时间范围 / 图例 / 全天 / 恢复      │
         │ └───────────────────────────────────┘
         │ [采样记录] [质量] [方法说明]
         │ 对应内容表格              点行 → 详情抽屉
```

手机左栏改抽屉，筛选可收起，关键门店／日期／队列保持可见；触控按钮至少44px，表格可变简要行卡或受控横向滚动，不缩小到难读。详情全屏打开，返回保持上一个状态。键盘焦点、按钮可读名称、图表文本摘要和颜色之外的状态标签一起实现。

## 8. 确认后的实施与验收

用户先确认这份结构和流程，再开始实际前端实现；不因技术原型已存在跳过确认。建议按同一套方案交付：

1. 先完成共用框架和主日历→日→店、工程导航、门店分析的可点击版本，供集中体验。
2. 完成主图、选点／表格／抽屉联动、无感刷新和手机流程，再接质量、预测、用餐页的分步内容。
3. 用真实公共归档及明确合成边界样例检查关键路径，确认后部署到原地址，保留旧资源回退。不重启采集，不更改本次三店期限／预算，不为纯样式改动重跑无关全套检查。

关键验收：从主月历进入某店某日并返回；工程切栏目保留私人输入；图点和表行指向同一真实记录；自动更新无跳动且保留缩放；快速改筛选无旧响应覆盖；空数组、失败、陈旧和未采集分别呈现；手机和键盘完成同一路径；所有可点击控件都有真实结果。

未来服务诊断、跨日对比、完整实际等待模型、真实过号率、推送、自动取号等分别列为后续功能，不为了导航完整而放无作用按钮。已有功能继续使用原数据接入合同：[统计接口规范](STATISTICS_INTEGRATION.md)、[官方来源适配](integration/OFFICIAL_SOURCE.md)。
