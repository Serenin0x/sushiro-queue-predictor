# 官方公开观测的匿名连续性合同

rc77新增本机导出和纯离线投影，rc78新增独立关联归档、只读统计及明确SSH传输模式。2026-10-11 E0457已把新独立三表归档部署到云端，同一受限入口兼容原v1及新关联包，原记录和摘要保持；旧库及原两日采样／范围／期限不改。103条原记录和完整关联已保存，原统计地址切到此归档。

## 用途与真实性

只有时间和前三个号码，不能区分分页边界、采集写者切换及漏掉的失败。新合同携带同店、同profile、同origin数据库前序记录的关联，避免将不相连的成功响应拼成速度。

原DB2中的run_id在每次SnapshotStore实例创建时随机生成，程序恢复不复用这个值。它表示写者实例边界，不是账号ID，也不能证明系统没有短暂挂起、网络中断或进程一直存活。新writer_id由随机run UUID及门店／来源范围生成UUIDv5，原run_id和本机样本ID不进入对象；不同门店的别名不相同。随机UUID的摘要不是密码签名，接收方不能认证导出者的原数据库内容，source_claims_verified必须为false。

## 导出

沿用packet-export原参数，追加`--with-continuity`。没有该参数仍输出完全相同的v1包。输出是新的0600文件、父目录0700，不覆盖已有文件、不读取查询凭证、不联网、不自动同步，也不推进持久游标。

一次限定1–3店、1000条，整个合同最多4MiB。原v1包放在packet中，观测ID、内容和record_sha256逐字不变。links依照本机样本ID选择顺序；每项携带匿名写者、前序观测ID／摘要／写者和link_sha256。前序位于本页外时，anchors保留其完整原v1公开记录及别名；锚点去重、排序，最多1000项，未使用或冲突锚点拒绝。

主记录及前序在同一SQLite只读事务中选择。每店只需为首条选择一次前序，后续采用页内最近记录。前序包含失败和不同写者，不为了获得可比速度而跳到更早成功样本；profile或origin不同的记录不混入。输入坏记录或前序损坏使整页失败，旧导出及当前采集不改变。

## 投影

`sushiwait.continuity.project_continuity_bundle`先校验完整结构／摘要／关联，再调用原官方月／日投影。仍保持单次官方详情GET、部分选择范围、未知新鲜度和真实叫号标签0。

| 状态 | 含义 |
| --- | --- |
| insufficient | 没有前序 |
| run_boundary | 前后写者实例不同 |
| failed_observation_boundary | 当前或最近前序失败，不跨失败比较 |
| day_boundary | 前序属于另一个北京时间日期 |
| time_order_or_duplicate | 时间倒退、重复或下一请求早于前次接收 |
| gap | 接收间隔超过可比阈值 |
| missing_queue_fields | 四队列中至少一个没有明确数组 |
| comparable_display_sets | 同写者、同日、无失败、时间可比且完整字段，允许比较展示集合 |

可比阈值默认120秒，只允许1–120秒，不能为15／5分钟采样放宽以输出精细ETA。只有comparable_display_sets给出interval_seconds及全数组集合的消失数；不是只比较前三位，也不是实际叫号数或过号率。汇总没有可比段时保持null而不是0。分页锚点可能早于所选记录范围，该语义明确保存，不增加覆盖槽位或成功查询数。

## 独立关联归档与接收（rc78源码）

`packet-check`与`packet-archive`只有明确追加`--with-continuity`才读取关联包。归档使用新的独立SQLite文件，三个精确表为archive_records、continuity_claims、continuity_bundles；schema标志仍为1，archive_kind另行区分。旧单表归档拒绝原地升级，新旧读取者互不猜测数据库类型。原记录正文和摘要不变，主记录及锚点、别名、关联、不可变整包在同一事务提交，冲突回滚整批。关联首次接收claimed_at和完整关联可用linked_at分开保存；分页锚点以后补齐关联不会反写旧记录或首个接收时间。失败后的提交状态区分not_started／unknown／committed，持久确认不完整时没有成功回执。

统计配置仍要求原七个字段，显式mode为`official_packet_archive_with_continuity`才选择新读取者。主记录和前序引用在同一只读事务核对，列值／正文／摘要／别名／接收时间不符，丢失前序或坏关联使请求503。没有关联的原v1观测仍保留，状态packet_continuity_unknown。比较只使用每条声明的最近前序，120秒门槛不放宽；统计读者不认证导出者、账号或真实数据库顺序，不能把关联摘要当签名。

新的SSH入口为`python -I -m sushiwait.continuitytransport --view-file ...`，只接受固定`sushiwait-official-continuity-v1`或原v1命令，且必须选择新配置。操作方预先准备0700的bundles和packets目录；路径由本机固定配置决定。新包先完整校验及私有不可变文件持久化，再事务归档，成功才返回严格版本2回执。回执包含整关联包／原packet摘要、全部原记录（含锚点）的ID与摘要、逐项关联ID与摘要、新增及去重计数。旧接收器及原forced command继续拒绝新格式。

`packet-deliver-ssh --with-continuity`明确选新命令；主机固定校验、专用key、无shell／转发、单次发送／时限、256KiB回执、原包保存和不推进采集游标均保持。`packet-confirmation-ssh --with-continuity`离线核对历史版本2回执，不打开key、不联网，不证明服务器当前仍保留记录。默认参数和旧v1回执保持原语义。
