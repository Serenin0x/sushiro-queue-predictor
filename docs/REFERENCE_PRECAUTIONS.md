# 已有号码的页面风险提示

rc69新增原创`reference-alerts.js`，实际接入`statistics.js`及同源静态资源。本人输入号码、当天取号时间并确认门店／队列后，页面用最新队列观测与现有历史＋实时参考生成提示。可选计划到店时间及叫号偏移只在浏览器内存；+10是希望到店后十分钟叫号，−10是希望提前十分钟叫号，与预测误差分开。

## 实际判断

| 依据 | 提示 |
| --- | --- |
| 本人原号码逐字出现在最新前三位 | 立即核对官方号单并准备到场；不确认实际已叫号 |
| 连续可比观测中，曾出现的原号码现不在列表 | 立即核对官方号单；不认定已经过号、入座或取消 |
| 首位参考已达到或越过本人位置 | 核对官方状态；号码差不是前方桌数 |
| 现有模型给出突发加速，或新观测使参考提前至少5分钟 | 提示重新安排到场；5分钟是未校准的提示阈值，不是保证 |
| 较早参考情景早于本人计划到店 | 提示可能需要提前到场；场景范围不是校准后的过号概率 |
| 最新响应超过90秒、失败、时间异常或绑定错误 | 撤回当前风险判断和预测，提示核对官方号单 |

保留原号码字符串，0200与200不互认展示证据。数量请求独立失败不会抹去有效队列展示；有效空列表与失败分开。店铺、日期、队列、本人号码、取号时间、到店计划变化后清除旧状态；逆序／同时间冲突不覆盖原证据，长缺口／运行边界／参考倒退不会制造“曾见后消失”。参考结果须同队列、同最新响应，不能使用迟到的旧模型。

同一来源响应重复读取不会把旧结果当新变化，也不重复修改ARIA提示文字；已发生的提前变化在该响应期间保持，下一新观测再评估。号码出现过仅说明有限展示中的观测，不能推断实际首次叫号时刻。

## 采集和提醒的明确边界

模块计算前15分钟30秒、其他60秒的来源更新目标，综合计划到店、带符号目标及较早情景；号码出现／消失或加速也请求30秒。但公共页面没有写入私人采集需求接口，`source_interval_applied=false`，当前不会改变服务器147店背景60秒采集。30秒页面读取与30秒来源采集是两件事。

这次实际实现页面可见提示，`notification_sent=false`、后台送达未接。保持页面打开时随既有30秒读取和15秒本地年龄重验更新；关闭／休眠／手机后台不承诺送达。没有取号／取消／重排、个人上传、模型付费调用或官方查询。新页面源码与云端冻结rc64分开，部署事实看最新交接。

新模块可由新视觉页面直接复用，`createTracker().update(detail, options, forecast)`返回不可变状态；一个私人范围使用一个实例，改变范围或结束追踪调用`reset()`。入口与行为检查见[源文件](../src/sushiwait/web/reference-alerts.js)、[专项及真实页面接线检查](../tests/reference-alerts.test.js)。完整开发顺序见[核心开发计划](CORE_DEVELOPMENT_PLAN.md)。真实风险概率、正常用餐误差、手机提醒送达与完整v1继续验收。
