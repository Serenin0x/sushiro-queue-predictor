**少一点盯号，多一点自由安排。**

想吃寿司，却不知道该几点取号、还要等多久、会不会突然过号？SUSHIWAIT 希望把这些不确定，变成有依据的用餐计划：结合寿司郎小程序的实时排队数据、历史规律和日期差异，帮助你安排取号与到店时间，把时间留给自己喜欢的事。

这是面向中国大陆寿司郎门店的独立开源项目。**目前处于实时数据接入验证阶段，电脑已成功读取中关村、西单、成都世豪三店的真实展示队列，并完成 60 秒／30 秒短窗采样；预测模型、用户小程序和自动排队仍在后续计划中。**

## 产品与模型功能

### 当前可以做什么

- **读到真实叫号数据**：从官方微信小程序确认实际查询地址，电脑已独立读取中关村、西单、成都世豪的堂食、预约展示队列。用户退出小程序后，后续电脑查询仍成功；完整保留号码、顺序和后缀。
- **找到试点门店，再用电脑采集**：目录接口已通过电脑查询，返回 147 条门店记录。三店各完成 60 秒和 30 秒的两轮短窗采样，加上正常凭证更新后的再次查询，共保存 18 份成功详情快照；长期稳定访问与全国完整覆盖仍待验证。
- **查看查询凭证的到期声明**：直接检查本机私有配置的到期声明、剩余时长与更新版本，显示是否触发到期前保护；不输出凭证内容。已观察到正常初始化返回新凭证，独立自动更新仍在验证中。
- **把一次正常刷新接到电脑查询**：可离线检查本人导出的捕获文件，明确选择正常单店请求，将完整上下文写入私有配置。到期或临近到期时拒绝导入；此功能不自动登录或续期。
- **为正常刷新准备更轻的接入方式**：新增同电脑短时接收工具，可接收正常门店查询中的完整新上下文，省去中间导出 HAR 的步骤。配套适配器与本机合成联动已通过检查；真实微信客户端接入仍待验证。
- **凭证到期，采集有序暂停与恢复**：在声明到期前 30 秒保护停采；可选择短时等待正常新凭证，通过检查后继续采集，并保持请求节奏。无需重启的恢复已通过合成联动测试，独立自动续期尚未实现。
- **把数据留住，也把来源分清**：使用 SQLite 保存公共快照，隔离新旧接口及真实、合成数据；保留字段缺失情况，支持历史变化与采集质量报告。
- **看清采集是否可靠**：报告区分请求失败、字段处理失败与本机停采，统计实际请求间隔、展示号码变化和字段状态。明确统计窗口，帮助发现异常；相同数据不会被当成刚更新的数据。
- **在上线前检查数据处理**：提供合成数据离线回放和自动化检查，验证号码保存、错误处理、来源隔离及旧数据库迁移。

真实字段单位、持续刷新、独立自动授权更新与全国覆盖尚未验收。目前的工具可用于接入验证，预测能力尚未开放。

### 正在奔向的用餐体验

以下是产品目标，尚未上线；每项实现并验证后，会同步更新这里的状态。

| 你想做的事 | SUSHIWAIT 的目标体验 |
| --- | --- |
| **现在取号，心里有数** | 预估当前取号后何时叫号，同时显示预测区间，让到店安排有依据。 |
| **想几点吃，提前规划** | 输入理想到店时间，获得建议取号时机。`+10` 表示到店后希望等约 10 分钟，`-10` 表示希望提前 10 分钟叫号；系统结合门店规则评估风险。 |
| **叫号变化，一处掌握** | 在我们的小程序中同步显示堂食与预约展示号、更新时间和刷新状态，减少两个小程序之间来回切换。 |
| **越接近用餐，越及时关注** | 用餐前 30 分钟按 60 秒、前 15 分钟按 30 秒的目标节奏更新；根据异常加速提前重算，给出过号风险与到店提醒。 |
| **遇到突然跳号，及时调整** | 结合具体星期、工作日、周末、节假日、午晚时段及月份季节趋势，分析可观察的号码变化，修正预测。真实过号率需额外事件证据。 |
| **到点取号，必要时调整** | 在授权和业务规则验证后，支持按计划取号、受控取消重排；如果重排会明显过晚，提醒提前到店。 |

目标是逐步支持大陆任意门店；每家店的实时数据、预测和操作能力将分别标明验证状态。预测误差通过真实结果校准，有限的展示号码不会被当作完整队列。

## 技术手段

当前使用 Python 3.11+ 标准库、固定 HTTPS 只读请求和 SQLite；保留分队列展示数组、字段存在状态与数据来源。通过有界离线捕获检查、同电脑短时上下文接收、私有上下文原子更新、到期保护与可选等待恢复完善采集可靠性。运行、凭证状态及批量采样步骤见 [数据验证手册](docs/DATA_ACCESS.md)，正常更新证据与进入条件见 [凭证更新说明](docs/AUTH_REFRESH.md)，辅助端与采集恢复见 [本机接入说明](docs/BRIDGE.md)。

后续规划使用 FastAPI、PostgreSQL、Redis 后台调度及统计与分位数预测。大语言模型用于提取有来源的商场活动、营业调整等外部事件，并辅助解释预测；其实际收益将通过回测验证。这些组件尚未实现。

前端在实时数据准备充分后开发。Logo 已选定 Unbounded 的红色像素刷痕矢量版，随 GitHub 浅色／深色模式自动切换；设计与字体来源见 [Logo 说明](docs/BRAND_DESIGN.md)，README 横幅与后续动态图文继续按独立视觉任务推进。
